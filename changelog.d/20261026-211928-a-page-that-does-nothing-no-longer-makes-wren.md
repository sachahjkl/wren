**A page that does nothing no longer makes Wren draw 60 frames a second** (`page/bindings_timers.odin` `timer_fire`, `browser/main.odin` `frame`): every `setTimeout` / `setInterval` callback that ran was a reason to build, paint and present a whole frame, whether or not it changed anything. YouTube keeps a 25 ms interval (and others) running on a page nobody touches: 58 timer ticks, 58 frames, 2 ms of GPU each, a thread of the graphics driver busy, and at 180 Hz the frames would have followed the monitor. A timer callback after which the document, the style rules, the pixels of the images and canvases, the selection and the address are the same is now `quiet` (the loop's existing notion: the media player's notices) and asks for no frame; a document that changed, a pending animation frame or a running animation still wake the frame loop. YouTube results page, nothing touched for 20 s: 58.7 -> 1.4 frames drawn per second, process CPU 10.5 % -> 2.3 % of a core; channel grid 59.1 -> about 1.4 frames per second, CPU 16.4 % -> about 3 %; video page paused 1.4 frames per second, 3.0 %. `tools\remote_e2e.ps1` section 6 (`examples/site/remote/idle-timer.htm`): a script runs 100 times and draws a few frames (a frame per tick before), and a timer that turns a box blue is still drawn.
