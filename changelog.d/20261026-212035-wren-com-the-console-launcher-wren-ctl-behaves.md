**`wren.com`, the console launcher: `wren ctl ...` behaves in cmd and PowerShell** (`src/tools/wrencom`, `src/desktop/launcher.odin`, [docs/console-launcher.md](docs/console-launcher.md)): `wren.exe` has no console, so from a terminal it gave the prompt back at once and a script got neither its output nor its exit code. A 150 KB console program (Odin, core library only) that `build.bat` builds to `build\wren.com` and `wren.exe` embeds (the release stays one file) is written beside `wren.exe` by Setup when "Add Wren to PATH" is on, removed when it is off, with `--desktop-integration=remove` and when Wren is uninstalled (only a file carrying its mark: another program's `wren.com` is never replaced or deleted; a PATH entry without it shows as "to repair"). cmd and PowerShell prefer it to `wren.exe` when `wren` is typed: for `wren ctl ...`, `--desktop-integration` or `--cli` it starts `wren.exe`, waits and ends with its exit code, handing it its own standard input, output and error (`> file`, `2>&1` and `| more` work), in a Job Object that kills `wren.exe` with it; for an address or a window option it lets go and the prompt comes back. `tools\wrencom_e2e.ps1` checks it on a scratch copy.
