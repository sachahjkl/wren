**Several windows in one process: a tab pops out into a window of its own and pops in to another, with its page as it is** (`src/browser/windows.odin`, `tab_drag.odin`; `Ctrl+N` new window; the tab menu's `Move tab to a new window` and `Move to window` submenu; the command `tab.move_to_new_window`; dragging a tab away from the tab bar (below or above a row of tabs, beside a sidebar: `browser.tabs.drag_detach`, `browser.tabs.detach_distance_em`) and dropping it on the tab bar of another window, with an insertion mark; `wren ctl windows`, `tab move <id> --to new|<window id> [--index n]`, `--win-id <id>` on any command, `Browser.getWindows`, `Target.moveTarget`, `windowId` in the answers of `Target.getTargets` and `Browser.getWindowBounds`): the page is not loaded again, its scripts, video, forms, history and zoom go on; only the pointer to the tab moves between the windows' lists. One process: the renderer, the fonts, the network and the pages are shared; each window has its own swap chain, toolkit state, tab bar, find bar, address field and pacing, and draws only when it has a cause (input, an animation, a frame it asked for, its page changing); a minimized window does not draw. A window that loses its last tab closes; closing a window closes its tabs; closing the last one ends the browser. The developer tools' docked panel follows the tab it was showing. The session file (`wren-session 3`, read back with `browser.session.max_windows`) keeps every window with its rectangle; a file of one window is the old format.
