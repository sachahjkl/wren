type: Changed

**bindgen in Odin** (`src/tools/bindgen`): the API generator can now emit the JavaScript-engine glue in **Odin** instead of C and read the description in **Odin** instead of `.widl`, so the whole chain moves off hand-written C.
  - `-emit:odin` writes `native/js/odin/wr_imports.odin` (the `wr_*` imports for an Odin guest: the counterpart of `native/js/gen/wren_api.h`) and `native/js/odin/js_interfaces_table.odin` (the realm's interface table and member metadata: the counterpart of `native/js/gen/bindings.c`), against `native/js/odin/wj_iface.odin` — tagged enums, `bit_set`, slice literals, no macros. `-emit:c` (the default, what `build.bat` runs) is unchanged.
  - `-convert-widl` migrates every `api/*.widl` to the Odin description form (directive comments `//@wb` for `raises` / `[Owned]` / `out bytes` / `[Exposed]` / handle metadata, plain Odin for the rest); the Odin reader produces the same model, so host bindings, guest SDK, docs and conformance are byte-identical (`-verify-roundtrip`).
  - The reader rejects, with the file and line, parameter / field names that are Odin keywords, `out` parameters that are not bytes, and enum / flags bases that would truncate in the ABI.
