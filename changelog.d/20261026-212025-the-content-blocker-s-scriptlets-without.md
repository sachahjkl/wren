**The content blocker's scriptlets without JavaScript** (`src/blocker/dom_ops.odin`, `rewrite.odin`, `jsre.odin`, `scriptlet_route.odin`, `native/js/engine/qjs_blocker.c`, `fetch.Body_Filter`; table in [docs/blocker.md](docs/blocker.md)): the blocker no longer runs JavaScript in a page to do what it can do natively. The scriptlets that change the document (`remove-attr`, `remove-class`, `set-attr`, `remove-node-text`, `replace-node-text`, `click-element`, `href-sanitizer`, `set-cookie`, storage writes...) are operations on the DOM fed by the engine's mutation journal (only what is new, once per batch, before the page styles and before every script, an inline script's text rewritten before it runs); the ones that rewrite what the page reads (`json-prune-fetch-response`, `json-prune-xhr-response`, `xml-prune`, `trusted-replace-*-response` and the new filter option `=`, and the JSON literals in a page's own markup such as `var ytInitialPlayerResponse = {...}`) are a body filter of the loader, in the stream, before the page sees the response; the ones that change what an API does (`set-constant`, `abort-on-property-*`, `abort-current-script`, timers, `no-fetch-if`, `no-xhr-if`, `addEventListener-defuser`, `window.open-defuser`, `json-prune` on `JSON.parse`...) are C hooks installed in the engine before the first script (`blocker.hooks.native`; off keeps the JavaScript versions). Regular expressions are JavaScript's, with captures, in Odin (a step budget instead of backtracking blow-ups) and in the engine. The element-hiding scan of generic selectors also looks only at what the journal says is new.
