type: Changed

**The small compat set is native** (`native/js/runtime/web_compat.c`, members bound by the generator from the IDL of FontFaceSet, Permissions and VisualViewport): `document.fonts` (a `FontFaceSet` without font faces of its own, also in workers as `self.fonts`), `navigator.permissions` (`query()` gives a `PermissionStatus`, also in workers), `window.visualViewport` (reads the scroll offset and the viewport's size from the browser; the window's `resize` and `scroll` events reach it as trusted events), `alert` / `confirm` / `prompt` (a console warning, nothing shown), `Element.scrollIntoViewIfNeeded` and the WebKit-prefixed Fullscreen API (`webkitRequestFullscreen`, `webkitFullscreenElement`, `onwebkitfullscreenchange`...) are C in the engine, defined at pre-initialization, so a window's realm no longer runs JavaScript to make them. `prelude/compat.js` goes from 25.7 to 16.3 KB (what stays: `document.execCommand("copy" / "cut")` and the description of console arguments for the developer tools); the JavaScript heap of a fresh realm is 23 KiB smaller (1242 to 1219 KiB) and a window's realm starts about 0.08 ms faster (best of 20: 0.77 to 0.67 ms). Behaviour changes: the interfaces follow their IDL (`add`, `delete`, `has` and `check` need an argument; the `FontFaceSet` and `PermissionStatus` iteration and `Symbol.toStringTag` are the generated ones), and the viewport's events are trusted. New test: `examples/jsweb/compat.js` (jswebtest `compat`); `examples/jsdom/compat.html` checks the Set methods.
