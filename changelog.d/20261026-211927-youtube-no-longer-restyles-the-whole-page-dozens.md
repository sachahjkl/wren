type: Fixed

**YouTube no longer restyles the whole page dozens of times while it changes pages** (`style/restyle_dom.odin`, `style/invalidation.odin`): the style engine keeps, for each `:has()` of tags / classes / attributes (YouTube: `:has([role]:not([aria-hidden]) .ytwChannelBlocksViewModelHost) *`), the elements that make its answer true, and restyles the anchor's subtree only when the answer flips. Three things made it flip all the time. (1) The "an attribute the chain reads changed above a member" flag was set once and never cleared: after the first such change every later batch of DOM changes was taken for a flip until the next full pass. (2) A class change on any ancestor counted as a change of the chain, though only the compounds before the last one are tested on ancestors (the last one is the member, which the set follows). (3) A member that leaves was assumed to have made the answer true, though it never had an element matching the head `[role]:not([aria-hidden])` above it (`Has_Members.held`). Measured on `https://www.youtube.com/results` and a click on a video (`tools\yt_profile.ps1`): full style passes caused by "too much changed" 54 -> 1 (1.66 s -> 0.01 s) while the results page loads, and 83 -> 7 (3.7 s -> 0.5 s) in the 30 s around a click on a video; script readings of the layout (`clientWidth`, `getComputedStyle`) 6.2 s -> 3.1 s; the longest freeze at a click 2.0 s -> 0.9 s. `WREN_RESTYLE_TRACE=1` now names the `:has()` anchor, why its answer was taken for a flip and what the dirty flags came from.
