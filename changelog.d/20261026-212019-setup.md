**Setup**: Wren is its own installer. A modal dialog (menu and palette command "Setup...", `wren.exe --setup`, and by itself at the first start of a release copy that is not the installed one) installs this copy into `%LOCALAPPDATA%\Programs\Wren` (`Wren Dev` for the development channel; any folder, checked: absolute, creatable, not the system's), with what the release package ships beside `wren.exe`, and manages the installation: options (Start menu shortcut, desktop shortcut, `wren` on the user PATH, registration as a web browser with a button to Default apps, a daily check for updates), Modify, Repair, Replace installed copy (this copy replaces the installed one, also while that one runs: its file is renamed to `.old` and removed at the next start), Move installation, Uninstall (shortcuts, PATH entry, registration, the Settings > Apps entry and exactly the files the manifest `wren_install.txt` names; a running copy's own file is deleted once the process ends), and **Use standalone** (carry on without installing; remembered in the profile, never asked again). The state is read from the disk: not installed, running installed, running another copy, older than installed, to repair. Nothing needs administrator rights. Never opens by itself for development builds, `--profile`, temporary or portable profiles, or with `WREN_DESKTOP_INTEGRATION=off`; closing it without an answer asks again only after an update. A file `wren.portable` beside `wren.exe` makes a portable copy: its profile is `<folder>\data`. `tools\setup_e2e.ps1` drives the real dialog on a scratch desktop.
