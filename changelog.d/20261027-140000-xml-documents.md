**XML documents complete** (`dom.Xml_Kind.Element`, `DOMImplementation_createDocument`, `Document_createXMLElement`): `document.implementation.createDocument()` makes an `XMLDocument`; `createElement` / `createElementNS` of an XML document keep the name's case (no upper-cased `tagName`, the XHTML namespace only in an `application/xhtml+xml` one); attribute names keep their case on the elements of XML documents; `getElementById` searches the document it is called on (it searched the page's for a `DOMParser` or `createHTMLDocument` document); pages served as `application/xhtml+xml` (and `.xhtml` / `.xht` files) are parsed as XML, a parse error shown as a `<parsererror>` page.
  - `DOMParser`'s XML documents are now `Document` objects, not `XMLDocument` (as in browsers).
