**`wren ctl reset`, `checkpoint`, `wait quiet` and the process's numbers: one running Wren for many scenarios** (`src/browser/remote_state.odin`, [docs/remote.md](docs/remote.md)): a test that starts a Wren for every scenario pays its start, its close and the CPU of a start-up that has to settle before anything at rest can be measured. `reset [--keep tabs,data,prefs,window,history] [--url address]` puts the running Wren back to a clean state in about 60 ms: the commands other clients wait on end with an error, developer tools, search bar, palette, element picker, full screen and downloads close, one blank tab is left (with it go the other tabs' zoom, scroll, history and logs), cookies, localStorage, sessionStorage, IndexedDB, the HTTP cache, HSTS, the CORS preflight cache, the browsing history and the closed tabs are emptied, and the preferences (every layer, `config.snapshot` / `restore`) and the window return to what they were when the Wren started. `checkpoint save | restore | list | delete <name>` keeps preferences, window, tabs (address, zoom), cookies (session ones too) and localStorage, and restores them. `wait quiet` waits for the process to be at rest (nothing loading, at most `browser.remote.quiet_cpu_ms` of CPU time in `browser.remote.quiet_ms`), decided in the browser instead of by a script sampling the process's CPU for seconds; `--idle-ms` per wait. `stats` gives the process's pid, uptime, CPU time, threads, handles and GDI / USER objects, and the counts a reset empties. `pref set --override` changes a value `--pref` fixed, `pref reset <name> | --all` puts preferences back, `shot --count n --interval ms` takes n pictures over one connection. New preferences `browser.remote.quiet_ms`, `quiet_cpu_ms` and `max_checkpoints`.
