**Two browsers run in one process, each on a thread of its own** (docs/architecture.md, "Where state lives"). The last globals of one App, one window or one page in `src/browser` and `src/page` are gone: the shell's (the page renderer, the status bar, the remote channel, the page thread, the developer tools' metrics and colours, the paint settings, the drag, the content blocker's shell, about:history and about:downloads, the video players...) are fields of `App`, and what an App's pages share is `page.Pages` (`App.pages`: the embedder's hooks, the image cache, the script compile service, the style threads, the Cache API, file system, service worker, Web Locks and storage bucket stores, the message ports, the shared workers), which the page package reaches through `page.the_pages`, bound to the threads that run the App's pages (its loop's, its page thread's, a worker's, a compile thread's). What the Apps share (the Wasm engine, the bytecode cache, the image decoders, the layout threads, the decoded web fonts, the crash session) is set up by the first App to start and let go of by the last to end (`browser/process_share.odin`: one atomic word, no lock). The lint of globals knows no `app`, `window` or `page` class any more, and reads the globals of `when` blocks too (it had missed the profiler's). `src/tools/e2e/two_apps.odin` runs two Apps at once on two threads: each sees only its own tabs, pages, storage, BroadcastChannel messages and frame, and nothing of either is left after. The toolkit keeps the interface state it draws with in one variable of the process (`ui/state.odin`, `g`): until it is the thread's, the two Apps' own threads take turns between the test's steps. Also: the content blocker's, the fetch service-worker hook's, the canvas glyph shapes' and the parallel wait hook's state is their thread's; the appearance watcher and the profiler's sampler carry their App instead of reading a global from their own thread.
