**DOMParser for XML** (`DOMParser.parseFromString` with `application/xml`, `text/xml`, `image/svg+xml`, `application/xhtml+xml`; package `xml`, `page.DOMParser_parseXMLNode`): a non-validating XML 1.0 parser with namespaces makes an `XMLDocument` (its `contentType` the type given, `location` null): elements in their namespaces (SVG and XHTML ones are the browser's SVG and HTML elements, other names keep their case), `CDATASection`, `ProcessingInstruction` (`target`), comments, the doctype, entity references (the predefined ones, character references, entities declared with a value in the internal subset). A text that is not well-formed gives a document whose element is `<parsererror>` saying what and where (line and column). `XMLSerializer` writes CDATA sections and processing instructions back.
  - Limits: attribute names are kept in lower case (the browser's DOM), `createElement` of an XML document makes HTML-world elements, `document.implementation.createDocument` is still not supported; XML pages loaded as documents (`.xhtml`) are not parsed as XML.
