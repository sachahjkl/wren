**Chrome DevTools Protocol / WebDriver BiDi adapter** (`remote.cdp.enabled`, `--remote-debugging-port=N`): a local WebSocket server that lets standard tools drive Wren — Puppeteer and Playwright (`connectOverCDP` / `connect`), Chrome DevTools, and WebDriver BiDi clients — speaking to the same command engine `wren ctl` uses (`src/browser/cdp.odin`, `src/remote` ws + tcp server). It serves `/json/version`, `/json/list`, `/json/new`, `/json/close`, `/json/activate` and `/devtools/{page,browser}/<id>`, and a useful subset of CDP (`Browser.getVersion`, `Target.*`, `Page.navigate/reload/captureScreenshot`, `Runtime.evaluate`, `DOM.*`, `CSS.getComputedStyleForNode`, `Input.*`, `Emulation.setDeviceMetricsOverride`/`setUserAgentOverride`, `Security.setIgnoreCertificateErrors`, `Browser.close`, and `Page`/`Runtime` events) and BiDi (`session`, `browsingContext` navigate/getTree/captureScreenshot, `script` evaluate/callFunction). Security: it binds `127.0.0.1` only, refuses a handshake whose `Host` or `Origin` is not loopback (the DNS-rebinding guard), is off by default, and does only what the user could do in the window. The port (0: the system picks one) is written to `DevToolsActivePort` in the profile, as Chrome does.
