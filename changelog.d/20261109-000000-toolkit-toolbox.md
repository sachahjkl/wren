**The tools hash and download with the toolkit's toolbox package** (`toolbox.sha256_hex`, `toolbox.sha256_file`, `toolbox.download_pinned`, `toolbox.env_with`), shared with gui_toolkit's tk and opencode native's occtools: `tooling.sha256_of`, `tooling.sha256_of_file` and `tooling.merged_env` are gone, and `tooling.download_pinned` only says why a download failed in the step's log. A pinned file of a GitHub release now comes through GitHub's API when its download fails, and on Windows the download uses the system's own curl. `tooling.run` and `tooling.capture` stay Wren's: they hold a process tree together, measure its CPU time and capture both output streams.
