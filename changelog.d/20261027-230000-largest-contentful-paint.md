**Largest Contentful Paint** (`PerformanceObserver` type `largest-contentful-paint`, `LargestContentfulPaint`, prefs `performance.largest_contentful_paint_entries`, `performance.largest_contentful_paint_min_bpp`) : each real paint of the shell reports the largest contentful element inside the viewport (an image, a video poster, a CSS background image, or a block of text), with `renderTime`, `loadTime`, `size` (the visible area in CSS px), `id`, `url` and `element` (null once it leaves the document, as the spec says), and `toJSON()`. A bigger candidate replaces the last; the algorithm stops at the first user interaction. Excluded as the spec requires: opacity 0, visibility other than visible, a full-viewport background, and low-entropy images (below `performance.largest_contentful_paint_min_bpp` bits per displayed pixel). Fed natively from the layout the shell painted, no JavaScript. `PerformanceObserver.supportedEntryTypes` lists it.
