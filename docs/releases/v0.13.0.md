# Wren 0.13.0

**Wren 0.13.0 cuts the Linux release binary by 15 MiB, adds live window carry for Wayland tab tear-off, speeds up animated 2D canvas and inline SVG rendering, and adds CSS `image-rendering` nearest-neighbour sampling.**

This is still a beta, under development.

### Highlights

- **Smaller Linux release binary (78.36 MiB to 63.69 MiB)**: minimal Wasmtime 49.0.3, the WebGPU C API (v29.0.1.1 ABI), WebGL (wgpu 29.0.3), and resvg 0.50.0 now build inside one Rust static library. This removes duplicate Rust standard libraries, duplicate wgpu/naga/ash and font stacks, and prebuilt Wasmtime and wgpu archive downloads.
- **Live window carry for Wayland tab tear-off**: dragging a tab out of a tab bar on Wayland compositors with `xdg-toplevel-drag-v1` detaches and carries a real browser window attached to the pointer. The carried window renders live frames, re-attaches when dropped on a Wren tab strip, and falls back to `application/x-wren-tab` on other compositors.
- **Faster animated 2D canvases, inline SVGs, and filters**: software 2D canvases use sparse 64×64 tile tracking for `clearRect` and partial uploads, plus direct premultiplied RGBA8 uploads with on-demand mipmaps. Effect-cache invalidation tracks per-image generations so static `filter` and `drop-shadow` layers stay cached, and animating inline `<svg>` elements reuse one GPU texture.
- **CSS `image-rendering` (`pixelated`, `crisp-edges`)**: pixel art and crisp icons render with nearest-neighbour sampling on `<img>`, `<canvas>`, `<video>`, inline `<svg>`, and CSS `background-image` and `mask-image` layers, including `-moz-crisp-edges` and `-webkit-optimize-contrast`.
- **Off-thread storage I/O and shared tab layout views**: File System Access operations and cold Cache API reads run on the blocking worker pool and cancel safely when a page closes. Each tab reuses one cached `lay.View` across paint, observers, hit-testing, cursor resolution, and DOM layout queries.
- **Broader Linux testing and JavaScript fuzzing**: `test_all` on Linux runs every portable `src/browser` unit test automatically, and `wrentool fuzz` fuzzes the JavaScript engine front end, interpreter, and bytecode reader (`js_src` and `js_bytecode`).
