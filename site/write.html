Write a page

Two ways to write a page: JavaScript, as anywhere, or WebAssembly alone. Wren runs a page's scripts, classic or modules, and what it does not implement is simply absent. Or the page names a module that exports wb_main and calls the browser through the generated Odin SDK; the whole API, with its ABI, is in docs/api.

The same page, two ways

hello/main.odin
package hello

import "web:web"

on_click :: proc "contextless" (user: i32, ev: web.Event) {
	out := web.Document_getElementById("out")
	web.Node_setTextContent(out, "Hello from WebAssembly!")
}

// called once the document is parsed
@(export)
wb_main :: proc "contextless" () {
	button := web.Document_getElementById("greet")
	web.EventTarget_addEventListener(button, "click", on_click)
}
the same page in JavaScript
<script>
document.getElementById("greet").addEventListener("click", () => {
  document.getElementById("out").textContent = "Hello from JavaScript!";
});
</script>
index.html
<!doctype html>
<meta charset="utf-8">
<title>Hello, Wren</title>
<script type="application/wasm" src="hello.wasm"></script>
<button id="greet">Say hello</button>
<p id="out"></p>
build (from a clone of the repository)
odin build hello -target:freestanding_wasm32 -no-entry-point ^
  -default-to-nil-allocator -collection:web=sdk/odin ^
  -out:hello.wasm -o:size

The module above compiles to 702 bytes. Open index.html in Wren (a file:/// address or a Windows path works) and click the button. For the JavaScript version, put the script at the end of the page instead of the module.

What a page can use

The web API

25 modules, 672 functions: DOM, events, timers, fetch, WebSocket, workers, storage, URL and encoding. Described once in api/*.widl, generated for Odin, documented with its ABI for other languages.

JavaScript, if you want it

Classic scripts, ES modules and import maps, defer and async, document.write, inline handlers and javascript: URLs. A member Wren does not implement is absent, so feature detection tells the truth.

No build step for the page

Wren loads file:/// addresses and Windows paths as well as HTTPS. A page can be one .wasm module and one HTML file, opened from disk.
