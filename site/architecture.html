Architecture

Wren is one executable, written in Odin, with a handful of statically linked libraries. This page walks through the parts and the rules that hold them together. The source is the reference: github.com/sachahjkl/wren.

The packages

PackageRole
baseScopes (an ownership tree with cleanups) and generational handles with stable pointers.
hostThe event loop: thread-safe posts with coalesced wake-ups, timers, a pool for blocking work.
netTransport only: HTTP(S) on asynchronous WinHTTP, per-host and global queues, back-pressure, cancellation.
fetchThe policy layer of the Fetch Standard: modes, CORS and preflights, credentials, redirects, HSTS, referrer policy, mixed content, MIME checks.
url · cookies · csp · httpWHATWG URLs and the Public Suffix List, the cookie jar (RFC 6265bis), Content Security Policy 3, headers and MIME types.
html · domHTML parsing with Lexbor, charset sniffing; the document tree and event dispatch (capture, target, bubble).
css · styleTokenizer, parser, selectors, media and container queries; the cascade with layers, var(), a rule index, a Bloom filter and partial restyles.
layoutBlock, inline, flex, grid and tables, bidi and line breaking, incremental relayout, display lists cut into paint chunks.

images · webfontImage decoding on threads (WIC, and Rust decoders for SVG, WebP and AVIF), WOFF and WOFF2.
browserThe shell: window, tabs, navigation, address bar, painter and compositor, about:config, status bar, profiling.

Rules that keep it from breaking

  1. One ownership tree. Process, tab, navigation, page, then the page's instances, DOM, requests and timers. Closing a tab or navigating closes a scope; cleanups run newest first, children before parents, so nothing outlives what it points to.
  2. Handles, never pointers, cross boundaries. A handle is a generation and an index. A destroyed or recycled slot fails to resolve: late network events and callbacks for dead objects are dropped.
  3. One UI thread, everything else posts. WinHTTP's threads, the blocking pool, image decoders and the colour glyph renderer only post results back. The DOM and the Wasm instances of a page live on the UI thread; text measurement runs in parallel on layout threads.
  4. Mechanism and policy are separate. net moves bytes and never follows a redirect or stores a cookie. fetch decides, per hop, with the document's environment in hand. A module, a module load and a navigation all go through the same code.
  5. Everything is bounded, each bound with a reason. Six requests per host and 64 in total, at most 20 redirects, cookies per site and in total, the bytes a page may hold, the memory of a module, the duration of every call into it. The limits a user may want to change are preferences in about:config.
  6. A module cannot reach browser memory. Every address and length an import receives is checked against the module's own memory before the browser reads or writes it.

The WebAssembly boundary

Every import is described once, in a dialect of Web IDL (api/*.widl: modules, functions, typed handles, enums, flags, structs, callbacks, errors, availability in windows and workers). A generator, bindgen, writes everything else.

Host trampolines

One per import, defined directly on the Wasmtime linker. It checks addresses, validates UTF-8, looks up handles by kind, range-checks enums, then calls the implementation with ordinary Odin values. A missing or mistyped implementation does not compile.

The Odin SDK

sdk/odin/web: distinct handle types, strings and slices, (T, Error) results. Modules whose memory is 64-bit get the same imports with 64-bit addresses.

Documentation

docs/api: every function of the 21 modules, with the ABI, so that SDKs for other languages can follow.

Conformance tests

470 generated cases over 261 functions: addresses out of bounds, invalid UTF-8, dead handles, enums out of range, buffers too small. A pointer outside the memory is a trap, a bad argument is an error or a trap, never undefined behaviour.

Modules are compiled by Cranelift. Compiled code is kept in memory (keyed by the SHA-256 of the module) and on disk in the profile, authenticated with an HMAC whose key is protected by Windows DPAPI. Interruption uses Wasmtime's epochs, advanced by a thread that only runs while a call is in progress: an idle browser wakes nothing.

Rendering

Retained compositor

The display list is cut into paint chunks, recorded once as GPU pictures and replayed. Scrolling, sticky offsets and transform animations change a matrix or a slot; nothing is re-recorded. Only chunks whose content changed are recorded again.

Effects kept between frames

Filtered layers, backdrops and blended pixels are cached on the GPU while their content is unchanged; colour matrices are folded into the composition. Animating opacity or a blend runs no extra pass.

Colours like the web

Blending happens on sRGB values as other browsers do, gradients and box shadows are computed exactly in the shader, and text uses grayscale anti-aliasing with contrast tuned like Chromium's.

Frame pacing

The refresh rate is read from the display path, frames are stamped with the vblank they start on, and animations, requestAnimationFrame and smooth scrolling advance in whole periods. Nothing is drawn when nothing changes.
