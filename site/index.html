Wren

A browser where WebAssembly is the only engine

No JavaScript, no glue layer. Pages are real HTML and CSS; what they do is written in WebAssembly modules that call the web APIs as imports, resolved by the browser itself. The engine is written from scratch in Odin, for Windows, and draws everything on the GPU.

The idea

Browsers carry a JavaScript engine and added WebAssembly next to it. Wren starts from the other end: WebAssembly is the only way a page runs code, so everything a page can do is a typed import with a checked ABI.

WebAssembly only

A page names its modules with <script type="application/wasm">. Every web API it may call is described once, in api/*.widl, and generated: 21 modules, 289 functions. A call into the browser costs about 7 ns.

Modern GPU rendering

Direct3D 11 through gui_toolkit: a retained compositor that replays recorded pictures, gradients and exact shadows computed in the shader, filters and blend modes as GPU passes, frames timed on the display's own refresh.

Written from scratch in Odin

Style, layout, painting, the DOM, the Fetch policy and the shell are new code in Odin. HTML parsing, the Wasm engine and image codecs are proven libraries; text, networking and decoding use what Windows provides.

Features

What the 0.1.0 preview does today. Every number on this site was measured on the development machine; the notes behind them are in the repository history.

Wasm pages, any number of modules

Modules are fetched concurrently and run in document order, each in its own instance sharing the DOM. Wasmtime 49 with Cranelift, a memory cache and an authenticated disk cache of compiled code.

A runaway module cannot freeze the page

Every call from the browser into a module has a deadline (wasm.max_call_ms, one second by default). A loop that never returns is interrupted; the page stays usable.

Web APIs as imports

DOM and events, timers, fetch, WebSocket, EventSource, workers, storage, URL, encoding, crypto, history, forms, performance. Each import checks every address against the module's memory before the browser touches it.

Modern CSS

Cascade layers, custom properties and @property, container queries, CSS Color 4 and color-mix(), math functions, flexbox, Grid Level 1 with subgrid, 2D transforms, animations and transitions.

Effects on the GPU

filter, backdrop-filter, the 16 blend modes plus plus-lighter and plus-darker, clip-path, masks, background-clip: text, linear, radial and conic gradients interpolated in sRGB, Oklab, Oklch, Lab and more.

Text on DirectWrite

Per-character font fallback, OpenType shaping and features, bidirectional text, line breaking with dictionaries for Thai, Lao, Khmer and Burmese, variable fonts, WOFF2, colour emoji in every font format.

Images

PNG, JPEG, GIF, BMP, ICO and TIFF through Windows; WebP, AVIF and SVG built in, whatever Windows has installed, with ICC colour management. Decoding runs on its own threads.

At the display's refresh rate

Frames follow the monitor's exact rate, with a budget of 1000/Hz. Wheel scrolling a page of 10,000 paragraphs: 1.4 ms CPU and 2.3 ms GPU at the 99th percentile, under the 5.56 ms of a 180 Hz screen.

Security from the standards

One policy layer for every request: CORS with preflights, cookies (third-party cookies blocked by default), Content Security Policy for Wasm modules too, HSTS, mixed content blocking, referrer policy.

Everything is configurable

about:config lists every setting with its description, default, bounds and unit: rendering, scrolling, fonts, network limits, Wasm limits. Nothing is hard-wired.

Frame statistics built in

The status bar draws a graph of every frame by phase. A click opens CPU and GPU percentiles, compositor, layout, memory and the time spent in Wasm.

A native window

Tabs in the title bar with Snap Layouts, pages that follow Windows' light or dark mode, text selection, context menus, find in page, page zoom, view-source: and a keyboard path through all of it.

What works, and what doesn't yet

Wren is a young engine with one goal, and an honest list of gaps.

Works well

  • Documents and CSS-heavy sites that do not depend on JavaScript. Compared pixel by pixel with Edge at 1280×720: 3.3% of pixels differ on example.com, 5.3% on rust-lang.org, 7.3% on webassembly.org.
  • Pages scripted in WebAssembly, with the DOM, events, timers, fetch, WebSocket, workers and storage.
  • HTTPS through WinHTTP, cookies, CORS and CSP.
  • Web fonts (WOFF, WOFF2, variable fonts), SVG, AVIF and WebP images.
  • Smooth scrolling, selection, find in page and zoom on long pages.

Not yet (or not ever)

  • JavaScript, by design. Sites that need it to show their content will not work; odin-lang.org, for example, picks its dark theme in a script.
  • No HTTP cache: every request goes to the network.
  • No downloads, HTTP authentication or blob: URLs.
  • No IME for East Asian input, no vertical writing modes, grayscale text anti-aliasing only.
  • 2D transforms only: no perspective or 3D.
  • Wasm threads and shared memory are off. The guest SDK exists for Odin only; the ABI is documented for other languages.
  • Windows only.

Write a page for Wren

A page is an HTML file that names a module. The module exports wb_main and calls the browser through the generated Odin SDK, sdk/odin/web. The whole API, with its ABI, is in docs/api.

hello/main.odin
package hello

import "web:web"

on_click :: proc "contextless" (user: i32, ev: web.Event) {
	out := web.Document_getElementById("out")
	web.Node_setTextContent(out, "Hello from WebAssembly!")
}

// called once the document is parsed
@(export)
wb_main :: proc "contextless" () {
	button := web.Document_getElementById("greet")
	web.EventTarget_addEventListener(button, "click", on_click)
}
index.html
<!doctype html>
<meta charset="utf-8">
<title>Hello, Wren</title>
<script type="application/wasm" src="hello.wasm"></script>
<button id="greet">Say hello</button>
<p id="out"></p>
build (from a clone of the repository)
odin build hello -target:freestanding_wasm32 -no-entry-point ^
  -default-to-nil-allocator -collection:web=sdk/odin ^
  -out:hello.wasm -o:size

The module above compiles to 702 bytes. Open index.html in Wren (a file:/// address works) and click the button.
