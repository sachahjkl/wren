# Changelog

What each version of Wren brings. The release notes on GitHub add the list of every change
([releases](https://github.com/sachahjkl/wren/releases); `tools/release_notes.ps1` writes them from
`docs/releases/` and the history).

## Unreleased

### Added
- **Desktop integration** (`src/desktop`, a box in `about:config` and two palette commands): Wren is one portable executable, and one switch adds or removes what makes it part of the user's desktop, in the user's own profile and without administrator rights. Windows: a shortcut in the Start menu (the executable's icon, and the AppUserModelID the windows declare, so that pinning and grouping work) and the registration as a candidate browser (`HKCU\Software\Clients\StartMenuInternet`, `RegisteredApplications`, the `WrenHTML` ProgID, URL schemes http and https and the file types of `browser.desktop_integration.file_types`): Wren then shows in Settings > Apps > Default apps, where the user picks the default (it never makes itself the default); a button opens that page. Linux: the XDG `.desktop` file (`MimeType=` for http, https and the file types) and the hicolor icons, then `update-desktop-database`. The box is ticked by what is on the disk, not by a preference; files that run another executable (the program was moved or updated) show "points to <path> - Update". The first run of a release build outside the installed copy opens Setup (below) instead of integrating silently (`browser.desktop_integration.on_first_run`). `wren --desktop-integration=install|remove|status` does it without a window, for an uninstall script. Removal deletes only what carries Wren's mark.
- **Setup**: Wren is its own installer. A modal dialog (menu and palette command "Setup...", `wren.exe --setup`, and by itself at the first start of a release copy that is not the installed one) installs this copy into `%LOCALAPPDATA%\Programs\Wren` (`Wren Dev` for the development channel; any folder, checked: absolute, creatable, not the system's), with what the release package ships beside `wren.exe`, and manages the installation: options (Start menu shortcut, desktop shortcut, `wren` on the user PATH, registration as a web browser with a button to Default apps, a daily check for updates), Modify, Repair, Replace installed copy (this copy replaces the installed one, also while that one runs: its file is renamed to `.old` and removed at the next start), Move installation, Uninstall (shortcuts, PATH entry, registration, the Settings > Apps entry and exactly the files the manifest `wren_install.txt` names; a running copy's own file is deleted once the process ends), and **Use standalone** (carry on without installing; remembered in the profile, never asked again). The state is read from the disk: not installed, running installed, running another copy, older than installed, to repair. Nothing needs administrator rights. Never opens by itself for development builds, `--profile`, temporary or portable profiles, or with `WREN_DESKTOP_INTEGRATION=off`; closing it without an answer asks again only after an update. A file `wren.portable` beside `wren.exe` makes a portable copy: its profile is `<folder>\data`. `tools\setup_e2e.ps1` drives the real dialog on a scratch desktop.
- **Update check** (`browser.update.check_daily`, off by default): once a day one request to GitHub's latest-release API (`browser.update.url`), compared with the running version, announced once per version by a notice; nothing is downloaded. The command "Check for updates" asks at once and opens the release page.
- **One Wren per profile** (`browser.single_instance`, on by default; `src/instance`): a link opened from another program, a `.html` file or `wren.exe <address>` while Wren runs opens a tab in the running window (restored if minimized, brought to the front) and the second process ends at once with exit code 0, instead of a second window on the same profile. The key is the channel and the profile folder, so `--profile X` and every test stay independent; only the same executable hands over (another copy opens its own window); a Wren that does not answer within three seconds does not hold the second start, which opens its own window and says so. `--new-window` (or `--no-single-instance`) opens a separate window; `WREN_SINGLE_INSTANCE=off` turns it off for scripts (`tools\test_env.ps1` sets it). Several addresses on the command line open one tab each.
- **`<video>` and `<audio>`** (`media.*` preferences): MP4 (progressive, moov at the end, fragmented) and WebM are parsed in Odin and decoded by the system's Media Foundation decoders: H.264 and AAC, Opus, and where the system has a decoder (Store extensions) AV1, VP9 and HEVC, on the GPU through DXVA. Decoded pictures stay in video memory (NV12 / P010 textures of the renderer's device, converted to RGBA in one draw when a new picture came), so a video takes `border-radius`, `object-fit`, `opacity`, filters and transforms as an image does, and the page is not painted again for each picture. The sound goes to WASAPI and is the clock; threads decode ahead of it. `HTMLMediaElement` follows the HTML state machine (resource selection with `<source>`, `readyState` and its events, `seeking`, `timeupdate`, `ended`, `play()` promises, the autoplay policy `media.autoplay.policy`, `buffered` / `seekable` / `played`, `error`, `canPlayType`), with built-in controls (`media.controls.*`) and a demo page (`video.html`).
- **Media Source Extensions** (`media.mse.*` preferences): `MediaSource`, `SourceBuffer` and `SourceBufferList` over the same player. A `SourceBuffer` parses what `appendBuffer` gives it (fragmented MP4, WebM) into coded frames with the timestamp offset and append window applied, in `segments` or `sequence` mode, replacing what new frames overlap, evicting the oldest when `media.mse.video_buffer_mb` / `audio_buffer_mb` are reached (`QuotaExceededError` when nothing can go); `remove()`, `abort()`, `changeType()`, `endOfStream()`, `duration`, live seekable range and the `update*` / `source*` events follow the specification. `URL.createObjectURL(mediaSource)` is played by a media element; a source the script dropped keeps playing while it is attached. A pictureless element (hidden, in a background tab) still reaches `ended`.
- **Canvas 2D** (`src/canvas2d`, `api/canvas.widl`, `src/page/canvas*.odin`, `native/js/runtime/web_canvas.c`; `canvas.*` preferences, demo `about:demos` > Canvas 2D): `canvas.getContext('2d')` is a real software rasterizer written in Odin (premultiplied RGBA8, 16 sub-scanlines with exact horizontal coverage, no dependency): paths, fill rules, strokes with joins, caps, miter limit and dashes, `arc` / `arcTo` / `ellipse` / `roundRect`, `Path2D` (including SVG path strings), the transformation matrix, `clip`, all 26 `globalCompositeOperation` modes, linear / radial / conic gradients, patterns, shadows, `filter` (blur, brightness, contrast, grayscale, sepia, invert, opacity, saturate, hue-rotate, drop-shadow), `fillText` / `strokeText` / `measureText` with the page's fonts (drawn as outlines, monochrome), `drawImage` from images, canvases, bitmaps, `ImageData` (`getImageData`, `putImageData`, `createImageData`; limited by `canvas.max_*`), `OffscreenCanvas`, `ImageBitmap` / `createImageBitmap`, `DOMMatrix` / `DOMPoint`, and `toDataURL` / `toBlob` / `convertToBlob` (PNG and JPEG through WIC). A cross-origin image without CORS taints the canvas (`SecurityError` on reads). The shell keeps one texture per canvas and re-uploads only the dirty rectangle, so a canvas at rest costs nothing. Sizes, memory and path / text lengths are bounded by preferences (`canvas.max_dimension`, `canvas.max_pixels`, `canvas.max_page_bytes`, `canvas.max_path_points`, `canvas.max_text_bytes`). Pages that probe `getContext('2d')` at start (duck.ai's Lottie, YouTube's polyfills) now run. Not implemented: workers, `<video>` as an image source, `imageSmoothingQuality` (stored only), `resizeWidth` / `resizeHeight`.
- **Fullscreen API** (`api/fullscreen.widl`, `src/page/fullscreen.odin`, `src/browser/fullscreen_shell.odin`; `fullscreen.*` and `browser.window.fullscreen_hint` preferences, demo `about:demos` > Fullscreen API): `element.requestFullscreen({navigationUI})` (a promise), `document.exitFullscreen()`, `fullscreenElement` (retargeted out of shadow trees; `ShadowRoot.fullscreenElement` too), `fullscreenEnabled`, `fullscreen`, `fullscreenchange` / `fullscreenerror` (bubbling, composed, at the element or at the document once it left), the WebKit-prefixed names (`webkitRequestFullscreen`, `webkitFullscreenElement`, `webkitExitFullscreen`, `webkitfullscreenchange`...) and the `:fullscreen` / `:-webkit-full-screen` pseudo-class, with the UA rule (fixed over the viewport, highest z-index, black ground). A request needs a recent click or key press, an element in the document, and the Permissions Policy `fullscreen` (an `<iframe>` needs `allowfullscreen` or `allow="fullscreen"`); a frame that goes fullscreen makes its container the fullscreen element of its parent. In the window: the same full screen as F11 with no tabs, address bar, status bar or find bar, Esc or F11 leave (the page does not see the Esc), another tab shown or a navigation leaves, the window returns as it was (a window already in F11 stays so) and the page keeps its scroll offset. The element is in a top layer in effect: the computed style of everything above it loses its stacking context, transform, filter, opacity, clip, mask and containment while it is fullscreen, so it covers the viewport whatever its ancestors do (and gets them back when it leaves). A second request replaces the first element. `Event.composed` is now right for events the browser makes.
- **Performance Timeline** (`src/page/timeline.odin`, `native/js/runtime/web_perf.c`; `performance.resource_timing_entries`, `performance.event_timing_entries`, `performance.event_timing_min_ms`): the entries the browser itself records. `performance.getEntriesByType("navigation")[0]` is a `PerformanceNavigationTiming` (the shell gives what it measured of the load: the time origin moves back to the start of the navigation, so `performance.now()` counts the network time as in other browsers; parsing, `DOMContentLoaded` and `load` times come from the document; connection steps take no time of their own); each request a document's scripts, styles, images, fonts and frames made is a `PerformanceResourceTiming` (from the loader's observers: `fetch.observer_add`); `first-paint` and `first-contentful-paint` (`PerformancePaintTiming`); slow input events and the first input (`PerformanceEventTiming`). `getEntries`, `getEntriesByType`, `getEntriesByName`, `clearResourceTimings`, `setResourceTimingBufferSize` and `PerformanceObserver` (types `navigation`, `resource`, `paint`, `event`, `first-input` besides `mark` and `measure`; `buffered`, `durationThreshold`) use them; the engine is only woken for the kinds an observer registered. `layout-shift`, `largest-contentful-paint`, `longtask` are still reported as unsupported. YouTube's and GitHub's startup read `responseStart` of the navigation entry.
- A same-origin frame's window (`iframe.contentWindow`) gives what pages take from it to have a pristine copy: the ECMAScript built-ins, the interface objects and constructors of the platform (`contentWindow.Node`, `.XMLHttpRequest`), `fetch`, timers, `console`, and `history` (an object with `History.prototype` and no brand: `contentWindow.history.pushState.call(history, ...)`, which is how YouTube's SPF script changes the address, works, calling it on the frame's own history raises a TypeError). A cross-origin window still gives nothing of it, and nothing of the frame's own state (`document`, `location`, `navigator`, its globals) is reachable from a same-origin one.
- **3D transforms, second round** (`paint.planes.*` preferences): planes that cut through each other are split along their line of intersection (a BSP, as Chromium's) instead of one being drawn over the other; `backdrop-filter` and `mix-blend-mode` act on the projected quad of a 3D-transformed element (through the shape of its border box, clip-path and mask); a plane is rasterized as dense as the screen shows it (no fixed ceiling of 3 texels per pixel: a memory budget, the part that shows when the whole does not fit, mip levels and anisotropic filtering for the reduction; it keeps its scale while it moves and is made sharper a moment after it stops); a pointer position on a form field in a 3D plane goes back through the exact inverse of the projection; a flat 3D-transformed child of a plain 3D-transformed element is composited on its own, so animating it does not rasterize the parent again (`paint.planes.detach_children`). `getBoundingClientRect`-side: `layout.box_of` gives the exact way back (`unproject`).
- **Built-in emoji** (`text.emoji`, `builtin` by default; `system` keeps Segoe UI Emoji on Direct2D): Noto Color Emoji (COLR v1, SIL OFL), shipped in `emoji\` next to `wren.exe` (`tools\fetch_emoji.ps1`, pinned by SHA-256; 4.9 MiB), drawn by an interpreter of the COLR paint graph written for gui_toolkit instead of a platform renderer: the same emoji on every platform, sharp at any size, the system's emoji font replaced even when a page names it, and no Direct2D device (about 150 MB less of private memory on a page of emoji, a page of 100 emoji painted in 85 ms instead of 510 ms). ZWJ families, skin tones, flags, keycaps, VS16 and tag flags are single glyphs; against Chrome / Edge on the same font the difference is under 1/255 per channel. `text.emoji.font` (another COLR font), `text.emoji.raster_samples`, `text.emoji.outline_cache`. The font and its license are in about:licenses and the release package.
- `text.renderer` (`atlas`, the default, or `slug`): with `slug`, text is drawn on the GPU from the glyph outlines (Eric Lengyel's Slug algorithm, credited in `THIRD_PARTY.md`): sharp at any page zoom, rotation or transform, with exact subpixel positions and nothing to re-rasterize when the zoom changes. Emoji stay bitmaps. `text.slug.pages` (video memory budget) and `text.slug.tolerance`.

- **About Wren** (`about:wren`, menu and command palette): the logo of the channel, version, commit, build, toolkit, Odin, Wasmtime and QuickJS-ng versions, "by Froment Software", the beta notice, the third-party software (`THIRD_PARTY.md`), and `about:licenses` with every license text (Slug's credit included).
- **Supporter licence** ([docs/licence.md](docs/licence.md)): a key signed offline with Ed25519 and checked in Wren without any network access, entered in `about:wren` (paste it, choose a file, or drop a `.wrenlicense` file). It changes one line of `about:wren` and nothing else: every version stays free and complete during the beta. `tools\license.ps1` makes the key pair and issues licences; `browser.license.*` preferences.
- **Crash reports**: a crash leaves its symbolized stack and a minidump in `<profile>\crashes`.

- **`navigator.clipboard`** (`writeText`, `readText`, `write`, `read`, `ClipboardItem`; `navigator.clipboard_write` / `navigator.clipboard_read`): `writeText` needs a focused document or a recent click or key press, `readText` both (the gesture is the consent: no permission prompt); text/plain only. **`ResizeObserver`** (with `ResizeObserverEntry` and `ResizeObserverSize`; content, border and device-pixel boxes), run at each rendering update before the intersection observations: GitHub's pages (React) stopped at its absence. **`document.fonts`** (a `FontFaceSet` that is always ready), **`navigator.permissions`**, **`window.visualViewport`**, `alert` / `confirm` / `prompt` that show no dialog and return what a dismissed one does, `Element.scrollIntoViewIfNeeded`, `document.execCommand("copy" / "cut")`.
- **Developer tools** (`src/browser/devtools*.odin`; F12 or Ctrl+Shift+I, Ctrl+Shift+J for the console, Menu > View > Developer tools, `browser.devtools.visible` / `dock` / `tab` / `size`): a native panel of the chrome, docked under the page, at its right, or floating over it (moved by its header, resized by its corner; "Dock" in its header, and a command for each), that takes room from the page. **Console**: the tab's messages by level (colors, a filter by level and by text), Clear, Pause, selection (click, Shift+click, Ctrl+A), copy (Ctrl+C, context menu), scrolling that follows the end, and the line that runs JavaScript in the page. **Elements**: the document as a tree (expand and collapse, Left / Right), the selected node's attributes and computed style, its box drawn over the page (hover and selection), and "Inspect" in the page's context menu. **Network**: the requests of the page (method, name, status, type, size, time) from the loader's new observer (`fetch.Observer`), per tab, restarted by each navigation, with Clear, a URL filter and a context menu. The older `browser.console.visible` now opens the panel on its Console tab.- **Shutdown diagnostics**: when closing the window takes more than `browser.shell.shutdown_warn_ms` (2 s), the browser logs once a second the step, the thread it joins and the threads still running (standard error and `shutdown.log` in the profile); after `browser.shell.shutdown_force_ms` (10 s) the process ends. The window disappears at once.

### Fixed
- **Custom elements**: `document.importNode()` (Polymer's way of stamping a template) and `cloneNode()` of a node of the document now upgrade the clone's elements of a defined name before they return (the contents of a template stay inert); and a custom element reaction's own DOM calls (a `connectedCallback` appending a stamped template) run the reactions they queued before they return, as the specification's stack of element queues does, where they used to wait for the outer reaction to end. YouTube's elements (`ytd-watch-flexy`'s `attached` called `preparePlayer()` on a player not upgraded yet) stopped on `TypeError: not a function`, which left the home page and the watch page without their contents.
- **Template contents have a document of their own** (HTML "template contents owner document"): `template.content.ownerDocument` (and that of every node in it) is an inert document, not the page's, so `ownerDocument.createElement("dom-repeat")` (Polymer prepares `<template is="dom-repeat">` this way) makes a plain element that is neither constructed nor given its attributes' callbacks; the documents of `createHTMLDocument` and `DOMParser` are inert the same way (`Document_createElementInert`). A script's insertion of nodes into a tree that is not connected no longer upgrades them (only a connected node is, as the specification says; the parser's `innerHTML` still upgrades what it makes). Before, moving a template's contents into another fragment constructed YouTube's elements inside them, which changed the child indexes Polymer had recorded, left `nodeList[i]` undefined and stopped with `cannot set property '__dataHost' of undefined`, and logged `Polymer::Attributes: couldn't decode Array as JSON: [[shownItems]]`; YouTube's watch page now builds its recommendations, comments and controls.
- **Fullscreen on a page that lays itself out again** (YouTube's player): the window's `resize` event is fired (once per rendering update whose viewport size differs from the last one; it was never fired), the `fullscreenchange` events and the promise wait for the window to have its new size and the page to have been laid out for it (`Fullscreen_Embedder.deferred`, `fullscreen_settled`; they run in the rendering update, before that frame's `resize`).
- **Developer tools, console**: a message of several lines (an error and its call stack) selected alone is shown one line per row in a pane under the list (the folders of the script addresses left out of the stack lines; copying still gives the whole text), instead of one line with `¶` marks only. An image answered with an empty body (a `204`, the connectivity pings `new Image().src = ".../generate_204"` that YouTube makes) fires `error` and no longer logs a warning.
- **Incremental layout** could crash (`has_block_child`, a dead box rebuilt) when an attribute that rebuilds an element's box changed inside a box the same pass made again alone (found on YouTube's home page): the boxes a plan took with it are no longer rebuilt as roots.
- A detached `new Image()` never loaded when `src` was set before it was attached to the document; it now starts loading at once (needed by `drawImage`).
- Closing the window after a heavy page (GitHub) could take 5 to 15 s or more: the Wasm module cache wrote every compiled module still queued to its disk cache, each one scanning the folder. It stops after 1.5 s and drops the rest.
- reCAPTCHA's "I'm not a robot" box (google.com/sorry) drew its checkbox in the corner of its card: an inline-block with `height: 100%` now resolves against its container's definite height, and a table beside a float no longer shrinks to its minimum width.

### Changed- User-Agent `Mozilla/5.0 (Windows NT 10.0; Win64; x64) Wren/0.3.0` (was `Wren/0.3`): the form sites expect, the version from the program, no `Chrome/` token. `network.user_agent` empty = this one.

## 0.2.0 — 2026-10-20

JavaScript, inside WebAssembly: WebAssembly is still the only execution engine.

### Added

- **JavaScript.** QuickJS-ng 0.17.0 compiled to a WebAssembly module, pre-initialized at build time and embedded in
  `wren.exe`; one sandboxed instance per page and per JavaScript worker, with a heap cap
  (`javascript.max_heap_bytes`), a clean stop for long scripts (`javascript.slow_script_ms`) and the Wasm deadline
  behind it. On or off globally (`javascript.enabled`) or per site (`javascript.sites.disabled`,
  `javascript.sites.enabled`). A bytecode cache in memory and in the profile. `JS` / `JS stopped` in the status bar.
- **Bindings generated from the specifications' Web IDL** (webref): 2,630 of 4,991 members implemented, the others
  absent ([docs/js/coverage.md](docs/js/coverage.md)). DOM, CSSOM, geometry, UI events, `MutationObserver`,
  `IntersectionObserver`, `PerformanceObserver`, ranges and traversal, custom elements, `CSS.supports` /
  `CSS.escape`; script loading as HTML specifies it (parser order, `defer` / `async`, `document.write`, ES modules
  and import maps, inline handlers, `javascript:` URLs, `<noscript>`, CSP for scripts); `fetch`, `XMLHttpRequest`,
  streams, `Blob` / `FormData`, URL, encoding, `AbortController`, Web Storage, history and location, navigator,
  performance, `crypto` and `crypto.subtle`, `matchMedia`, WebSocket, EventSource, `MessageChannel`, JavaScript
  workers, `structuredClone`, a minimal `Intl`.
- **Shadow DOM**: `attachShadow`, declarative shadow roots (rendered without JavaScript), named and manual slots,
  `:host`, `:host-context()`, `::slotted()`, `::part()` and `exportparts`, `:state()` and `ElementInternals`,
  constructable stylesheets and `adoptedStyleSheets`, event retargeting and `composedPath()`, `delegatesFocus`,
  `getHTML` / `setHTMLUnsafe`.
- **Conformance suites**: test262 (99.92 % of 82,220 runs) and web-platform-tests (4,494 test files, 106,188
  passing subtests), pinned, with committed expectations checked by `tools/test_all.ps1`.
- HTML presentational attributes and quirks mode; `text-align: -webkit-center`; `line-height: normal` from the font.
- Tabs with favicons, loading indicators, drag to reorder and middle-click to close; error pages by cause; downloads;
  optional session restore; more shortcuts (Ctrl+P notice, Ctrl+Shift+PgUp / PgDn, mouse back and forward buttons).
- Local files: Windows paths in the address bar and on the command line, drag and drop of files and folders, folders
  opening their `index.html` or a sortable list of their files, `about:about`; `examples/site/index.html` and
  `about:demos` list every demo by theme.
- Demos: `js.html`, `js-dom.html`, `shadow-dom.html`, `legacy-html.html`, script loading and web API pages.

### Changed

- Text placed vertically as in Chromium: font metrics rounded one by one, half-leading, `vertical-align`, flex lines
  bounded by `min-height`, centered button content, table cells and form control baselines, monospace and keyword
  font sizes.
- Image sizes come from the decoded image; `width` / `height` attributes give the aspect ratio before decoding.
- Shaders precompiled: the start page is drawn about 0.3 s after launch (1.8 s before). Resizing keeps the swap chain
  (a margin and a presented region instead of `ResizeBuffers`); media queries restyle only when their answer changes.
- The event loop runs due timers for at most `browser.loop.timer_slice_ms` per turn once one has run.
- User-Agent `Wren/0.2`.

### Fixed

- About 90 problems found by a review of the whole engine: use-after-frees (microtasks during host tasks, fetch,
  workers, streams), `file:` pages leaving their folder (escaped separators, junctions, links, alternate streams,
  device names), NTLM leaks through `file://server/share`, hostile content that crashed or froze the browser (huge
  `calc()`, exponential `var()`, cyclic `@import`, extreme transforms…), CORS on redirects, lost `localStorage` at
  exit, ten divergences of the incremental restyle and layout, `--pref` erasing profile values.
- Synthetic italics of static web fonts.
- Closing a WebSocket right after a message no longer ends in an error.
- Flaky tests fixed at their cause; CI no longer retries a failed step.

## 0.1.0 — 2026-10-19

The first public build: a browser for Windows where WebAssembly is the only execution engine, with no JavaScript.
Pages name their Wasm modules with `<script type="application/wasm">`; the web APIs are Wasm imports generated from
`api/*.widl`.

- **WebAssembly runtime**: Wasmtime 49 (Cranelift), compiled-code caches in memory and on disk, a deadline on every
  call, several modules per document, memory64, dedicated workers.
- **Web API from one description**: 21 modules, 289 functions, with generated host trampolines, Odin SDK,
  documentation and conformance tests.
- **HTML and CSS**: Lexbor parsing, cascade layers, custom properties, `:has` / `:is` / `:where`, media and container
  queries, Color 4 / 5, web fonts, transitions and animations.
- **Layout**: block, inline (bidi), floats, positioning, flexbox, grid with subgrid, tables; incremental and parallel.
- **Painting**: a retained GPU compositor on Direct3D 11, transforms, filters, blend modes, masks, exact shadows,
  gradients in every color space.
- **Text** on DirectWrite; **images** through WIC plus built-in WebP, AVIF and SVG.
- **Network and security**: WinHTTP, a Fetch Standard policy layer, cookies, HSTS, Content Security Policy 3.
- **The browser**: tabs, history, find in page, selection, zoom, view-source, `about:config`, frame pacing and
  statistics.
