# Changelog

What each version of Wren brings. The release notes on GitHub add the list of every change
([releases](https://github.com/sachahjkl/wren/releases); `tools/release_notes.ps1` writes them from
`docs/releases/` and the history).

## Unreleased

- Toolkit 0.40.0: rich text paragraphs (`ui.rich_paragraph`: mixed faces, code, links, one wrapping paragraph) and text selection outside fields (`.Selectable` labels and paragraphs, across boxes, Ctrl+C) for the shell's own panels; bold runs take the family's real bold face.

- **Text is shaped by Fontations, HarfRust and ICU4X by default** (the toolkit's native text backend, toolkit 0.39.0) instead of DirectWrite: `build.bat` builds it in; `WREN_TEXT=dwrite build.bat` builds `wren_dwrite.exe` with DirectWrite's shaper. Same widths and metrics on the toolkit's multilingual corpus, 2.6 times faster shaping; better: kerned Hebrew pairs close as the font says (DirectWrite drops their placements), words are found in Lao, Khmer and Myanmar lines, an emoji with its skin tone is one caret stop; simulated bold and italic are drawn as DirectWrite drew them. The system's fonts and their fallback still come from Windows. The `text.backend` preference (restart) picks DirectWrite back.
- **`WritableStream` follows the Streams Standard's algorithms**: the erroring state, one write or close in flight, `abort()` that waits for it and calls the sink's `abort`, the strategy's `size` and `highWaterMark`, backpressure through `desiredSize` and each writer's `ready`, each writer's own `closed`, and `controller.signal`. WPT `/streams/` (with `piping` now): 1662 of 2065 subtests, up from 1316 of 1565.
- **`ReadableStream.pipeTo` / `pipeThrough`** with `preventClose`, `preventAbort`, `preventCancel` and `signal`. Errors and closing propagate both ways, and a shutdown waits for the last write. **`CountQueuingStrategy` and `ByteLengthQueuingStrategy`** are implemented too.
- **`StorageBucket.getDirectory()`**: each storage bucket has its own origin private file system. Its `estimate()` counts it, it goes when the bucket is deleted, and its handles survive `structuredClone`.
- **Synchronous `XMLHttpRequest` in workers.** The worker's thread waits for the request, made as an asynchronous one would be. A document's synchronous requests are still refused.
- **Workers**:
  - an uncaught error that the `Worker`'s `error` event does not cancel reaches the page's `window.onerror`;
  - `requestAnimationFrame` works in dedicated workers (a 60 Hz clock);
  - a worker's script and `importScripts()` must have a JavaScript MIME type over HTTP(S);
  - a module shared worker whose imports fail fires `error` at its `SharedWorker`;
  - `new FormData()` works in workers.
- **The back/forward cache is measured**: `wren ctl stats` has a `bfcache` section. It gives the pages kept, restored and evicted, the back/forward traversals and how many found their page (`hitRate`), and why pages were refused, each blocker counted apart (`Unload_Listener`, `Web_Socket`, `Worker`...). It is checked by `tools\bfcache_e2e.ps1`.
- **Shared Wasm memory between realms, tried**: two Wasmtime stores on two threads share a memory and wait for each other (`src/wasm/shared_memory_test.odin`). Sharing a `SharedArrayBuffer` would also need the JavaScript engine rebuilt for Wasm threads, a new start-up snapshot and weaker isolation between a page and its workers; `docs/shared-memory.md` explains why it is not done now.
- **WPT `/workers/`**: 992 of 1323 subtests (75 %), up from 655 of 1014. `docs/wpt-workers.md` classifies the remaining failures by cause. The WPT test server now runs a few Python handlers ported to Go, and `.headers` files replace its `Content-Type`.

- **Workers from `blob:` URLs**: `new Worker(URL.createObjectURL(blob))` and `new SharedWorker(...)` run the Blob's script (revoking the URL right after the constructor is fine).
- **`unregister()` lets its clients finish**: an unregistered service worker takes no new page and is no longer found, keeps controlling the pages it controlled, and goes with the last one.
- **`clients.openWindow` and `WindowClient.focus` need a gesture**: a click or key press in a window of the site within `service_workers.window_activation_ms` (else `InvalidAccessError`).
- **Worker clients**: `clients.matchAll({type: "worker" | "sharedworker" | "all"})` lists the dedicated workers of its clients and the site's shared workers; **`navigator.serviceWorker` in a dedicated worker** shows its document's controller (`controller`, `ready`, `getRegistration`), and messages go both ways (`controller.postMessage`, `Client.postMessage` to the worker).
- **`new FormData()` in a worker no longer crashes the browser** (it reached for the forms of a document a worker does not have).
- **Nothing left allocated at exit** after service workers, workers and file system handles: the Cache API and file system stores are freed, a worker's last messages are handled before the loop goes, `getFile()` no longer leaks its file's description, and two small leaks of every session (the first tab list, the pointer table) are gone. `tools\sw_e2e.ps1`, `workers_e2e.ps1` and `fs_e2e.ps1` take `-Check` (the check build, which must exit clean), a step of `test_all`.
- **WPT `/workers/` measured whole** (its sub-folders too: 295 tests, 64.7 % of 1014 subtests); `tools\wpt.ps1 -Suites` runs a subset of the folders (and `-Update` rewrites only theirs).
- **No navigation timing entry in a worker** (`performance.getEntriesByType("navigation")` is empty there).

- **Origin private file system**: `navigator.storage.getDirectory()`, `FileSystemDirectoryHandle` (`getFileHandle`, `getDirectoryHandle`, `removeEntry`, `resolve`, `entries` / `keys` / `values` / `for await`), `FileSystemFileHandle` (`getFile`, `createWritable`, `createSyncAccessHandle` in dedicated workers), `isSameEntry`; kept in `<profile>/opfs/<storage key>/` with names encoded so that names differing by case or reserved by Windows are their own files; `opfs.max_bytes_per_origin` (`QuotaExceededError`), counted by `navigator.storage.estimate()`, removed by "Clear site data".
- **`FileSystemWritableFileStream`**: `write` (BufferSource, Blob, string, `{type: "write" | "seek" | "truncate"}`), `seek`, `truncate`, `close` replaces the file in one rename from a temporary file, `abort` leaves it; a sync access handle (`read`, `write`, `truncate`, `getSize`, `flush`, `close`) writes in place under an exclusive lock; a locked entry cannot be removed (`NoModificationAllowedError`).
- **`WritableStream`**, `WritableStreamDefaultWriter`, `WritableStreamDefaultController`: `new WritableStream(sink)` (start, write, close, abort, highWaterMark), `getWriter()`, `locked`, `desiredSize`, errors that reject what waits (`pipeTo` is not there yet).
- **File System Access**: `showOpenFilePicker`, `showSaveFilePicker`, `showDirectoryPicker` (`types`, `excludeAcceptAllOption`, `multiple`, `suggestedName`, `startIn`, `id`, `mode`) with the system's dialogs (toolkit 0.38.1 `platform.open_file_dialog` & co.), a user gesture required (`file_system.user_activation_ms`), `file_system.pickers`; handles on files and folders of the disk, `queryPermission` / `requestPermission` with a prompt of the browser (`file_system.write_permission`: ask, allow, deny); handles survive `structuredClone`, `postMessage` and IndexedDB.
- **Drops as handles**: `DataTransferItem.getAsFileSystemHandle()` and `FileSystem.root` of `webkitGetAsEntry()`.
- **`<input type=file>` uses the same Open dialog** as the pickers (toolkit `platform.open_file_dialog`).
- `WREN_TEXT=native build.bat release` builds `build\wren_native.exe`, whose text is shaped by Fontations, HarfRust and ICU4X (the toolkit's native text backend, built into the image decoders' library: one Rust library per program) instead of DirectWrite: the test pages draw the same to within 0.07 % of their pixels, shaping is 2.6 times faster, the exe is 2.2 MB larger.
- Kerning is kept under `letter-spacing` and `font-feature-settings` (toolkit 0.38.0: DirectWrite dropped its default features when given a list).
- Toolkit 0.38.2: `ui.text_edit` wraps long lines, grows with its content and gives its caret rectangle (for the shell's own editors).

- Text goes through the toolkit's new text backend interface (toolkit 0.37.0): DirectWrite is one backend among others, with the same result (pages captured before and after are identical); the `text.backend` preference (`default`, `dwrite`, `native`, at restart) picks the shaper of a build that has the native one.

- **`SharedWorker`**: one worker shared by every document of the origin (and storage key) that names the same script and name, hosted by a page of its own that shows nothing; `connect` events at its `SharedWorkerGlobalScope` (`onconnect`, `e.ports[0]`, `self.name`, `close()`), the document's `port` talks to it thread to thread; it stops when the last document using it closes (`{extendedLifetime: true}`: after `shared_workers.extended_lifetime_ms`); a script that cannot load fires `error` at its `SharedWorker` objects; `shared_workers.enabled`.
- **Module workers**: `new Worker(url, {type: "module"})`, `new SharedWorker(url, {type: "module"})` and `register(url, {type: "module"})`: static and dynamic `import`, `import.meta.url`, relative and absolute specifiers, one module map per realm; `importScripts` throws a `TypeError` there; messages wait until the graph ran.
- **Each kind of worker is its own realm**: `FetchEvent`, `Clients`, `ExtendableEvent`... exist in service workers only, `SharedWorkerGlobalScope` in shared workers only, `DedicatedWorkerGlobalScope` in dedicated workers only (the bindings generator knows `[Exposed=DedicatedWorker / SharedWorker / ServiceWorker]`); a service worker's global is a real `ServiceWorkerGlobalScope`.
- **Service worker versions**: installing, waiting and active versions, `updatefound` and `statechange`; a changed script waits while the active version has clients, `skipWaiting()` promotes it, the clients get the new one (`controllerchange`); each version keeps the script it installed (`<profile>/service_workers/<version>.js`).
- **Service worker updates**: `registration.update()` and `register()` fetch the script (`Service-Worker: script`, the HTTP cache bypassed unless `updateViaCache: "all"`), the same bytes install nothing; a navigation in the scope checks it when the last check is older than `service_workers.update_check_hours` (24); `Service-Worker-Allowed` lets a script control a scope above its folder.
- **Navigation preload**: `registration.navigationPreload` (`enable`, `disable`, `setHeaderValue`, `getState`), the navigation's request starts at once with `Service-Worker-Navigation-Preload`, `FetchEvent.preloadResponse` resolves with it, and a navigation the worker does not answer gets it instead of a second request.
- **Idle service workers stop**: after `service_workers.idle_ms` (30 s) without an event, the worker's thread and realm go; the next event starts it again.
- **Service worker clients**: `clients.matchAll()` lists every window of the scope (`includeUncontrolled`: of the origin; not those in the back/forward cache), `clients.get`, `clients.openWindow` (a new tab, resolved with its `WindowClient`), `WindowClient.navigate` and `focus` (shows its tab), `visibilityState`, `focused`, `frameType`.
- **Cache API: `Vary`, `ignoreVary` and URLs**: an entry matches only a request with the same values of the headers its response varies on (`Vary: *` never), `put` replaces only what its request matches, `ignoreVary` lifts it; `cache.keys()` gives the stored requests' headers; a response from the cache keeps its `url`.
- **`MessageEvent.data` after an `await`**: a message from a worker or a port is deserialized when its event is dispatched, so a listener that reads `data`, `origin` or `ports` later still sees them.

- **The drag picture of any element, wherever it is** (toolkit 0.35.2 `draw.offscreen_begin` / `render.readback_poll`): the element `setDragImage` names, or the dragged element's ghost, is painted alone into an offscreen target and read back, so an element placed off the page (`top: -1000px`), scrolled away or under others gives its picture; an element that is not rendered (`display: none`) gives the dragged element's ghost, as in other browsers. `wren ctl stats`: `dragPicture` (size, hot spot, middle pixel).
- **Dragging selected text of the document shows the selection**: its selected text with each line's highlight, faded like the ghost, over the window and for the system's drag, instead of the system's bare cursor.

- **`touch-action` directions**: `pan-left`, `pan-right`, `pan-up` and `pan-down` are their own (a gesture may only start by scrolling that way, then goes on along its axis, as the standard says), combined with the other axis and `pinch-zoom`, each group at most once.

- **AltSnap resizing: one picture per step** (toolkit 0.35.2 `ui.wake_due` / `ui.wake_in_ms`): the second frame of each step came from the loop woken by the `WM_SIZING` AltSnap sends before the step, which made a frame because a caret blink was asked for (not yet due); `wren ctl stats` now says why the frames of a resize were made (`resizeFrameCauses`: `Ui_Timer` 882 of 1544 before). `tools\altdrag_sim.ps1 -Variants altsnap`: 893 presents for 500 steps to 494, CPU 969 to 578 ms.

- **Service workers**: `navigator.serviceWorker` (`register`, `ready`, `getRegistration(s)`, `controller`, `controllerchange`, messages), `ServiceWorkerRegistration`, `ServiceWorker`; in the worker `install` / `activate` with `waitUntil`, `fetch` with `respondWith`, `message`, `skipWaiting`, `clients` (`claim`, `matchAll`, `get`, `Client.postMessage`).
