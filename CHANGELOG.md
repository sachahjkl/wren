# Changelog

What each version of Wren brings. The release notes on GitHub add the list of every change
([releases](https://github.com/sachahjkl/wren/releases); `tools/release_notes.ps1` writes them from
`docs/releases/` and the history). What is not released yet is in [changelog.d/](changelog.d/README.md), one file per
change, assembled here when a version is published (`tools/changelog.ps1`).

This file follows [Keep a Changelog 1.1.0](https://keepachangelog.com/en/1.1.0/); its version numbers do not follow
Semantic Versioning, since a patch version can add or remove features.

## [Unreleased]

## [0.6.29] - 2026-11-04

### Changed
- **The JIT calls the script's getters and setters** (`src/engine/jsrt/jit.odin`): a loop that reads a property through a getter of the script's (`get x() {...}`, a class's) or writes one through a setter, native or the script's, stays compiled, the accessor called as compiled code calls a function, an exception unwinding exactly once. A getter read in a loop 151 -> 78 ns, a setter 145 -> 81 ns, `getter access` of macro.js 184 -> 92 ns.
- **Compiled code allocates objects itself** (`src/engine/jsrt/jit.odin`): an object literal and the object of `new F()` (the constructor's `prototype` guarded) are made by the code, from the engine's own pool and list of cells, without a call to the engine; the collector's contract is unchanged (allocation never collects). `new Point(i, i)` 110 -> 51 ns, `{a, b, c}` 57 -> 28 ns.
- **The JIT reads `document`** (`src/engine/jsrt/jit.odin`): compiled code calls the native getter of an own accessor of the global object (`window.document`) when its value is read from at once (`document.createElement(...)`), an exception exact through the next read, which throws it; a call whose callee the translation cannot tell learns it at its first exit. The building loop of nodes10k is compiled: `build()` 9.0 -> 7.9 ms a frame with the JIT (the same without it).

### Fixed
- **A compiled loop of slow native calls is stopped like a slow script** (`src/engine/jsrt/jit.odin`): the compiled code gives the interrupt its turn once its native calls count for a poll, as the interpreter does; a `document.write` flood compiled by the JIT could run past `wasm.max_call_ms` before it, and the page lost its JavaScript engine.
- **Closures are made as fast as before the JIT's round 21** (`src/engine/jsrt/object.odin`): the search of a shape's transitions is inlined in `add_property` again, which it had left when the JIT began appending properties itself; with the JIT off, a closure made and called in a loop 565 -> 540 ns (531 before round 21). try/catch in a loop was not slower: 68.4 before round 21, 69.3 after, the same within its range.

## [0.6.28] - 2026-11-04

### Added
- **CSP Embedded Enforcement**: `<iframe csp="...">` (and `iframe.csp`) requires a Content-Security-Policy of the documents the frame shows. Its requests say which (`Sec-Required-CSP`); a page that agrees (`Allow-CSP-From`) or has a policy as strict is shown with it enforced, about:blank, srcdoc, `data:` and `blob:` documents take it, any other is refused as `X-Frame-Options` refuses. The `sandbox` directive of a Content-Security-Policy header now sandboxes the document.
- **`document.domain` setter**: a page and its frames of other ports or subdomains of one site that set the same `document.domain` reach each other's documents and windows (HTML's same origin-domain), and a navigation between them fires the target's `navigate` event; a value that is not the host or a registrable suffix of it, or a sandboxed document, throws a `SecurityError`; under `Origin-Agent-Cluster: ?1` the assignment changes nothing.
- **`::backdrop`** of the top layer: a modal dialog, a showing popover and the fullscreen element get a box the size of the viewport just under them, above the page (the UA's faint grey behind a modal dialog, black behind a fullscreen element, styled by the page); a click on a dialog's backdrop is the dialog's, a popover's lets it through. `getComputedStyle(el, "::backdrop")` and `"::placeholder"` answer, and `::part()::backdrop` is a valid selector.
- **`::placeholder`** on text fields and textareas: its color, opacity, font (size, family, weight, style) and `text-align` apply; the default is Chromium's grey (`#757575`) instead of the field's color faded.
- **Scroll anchoring** (CSS Scroll Anchoring, `overflow-anchor`): when content above what you are reading changes size (an image that loads late, a banner inserted or removed), the page keeps showing the same content instead of jumping; not at the top of a page, not where `overflow-anchor: none` says so. Reading `scrollX` / `scrollY` from a script gives the offsets after the layout the script's changes call for.
- **The `scrollend` event**: once a scroll container or the page stops moving (a script's scroll, the wheel, the keys, smooth scrolling), at the first frame where it did not move again; an element's does not bubble, the document's reaches the window. A `scroll` event now also fires for a container a script moved and put back before the next frame.

### Changed
- **WPT runner: windows with a history, a second http port**: the windows a test opens keep a session history across their documents and follow `history.back()`, `history.go()` and `navigation.traverseTo()` between them, and the test server answers wptserve's second http port (`{{ports[http][1]}}`), so tests of another origin on another port run instead of timing out.
- **Styling no longer pays for `::backdrop` on every element**: the rules of `::backdrop` (the browser's own, and resets such as Tailwind's `*, ::before, ::after, ::backdrop`) are tried only for the elements of the top layer (a modal dialog, a showing popover, the fullscreen element). A page of 10 000 elements restyled whole every frame: its style stage went from 0.84 to 0.75 ms. The static C runtime Wren links since Odin dev-2026-11 was measured against the dynamic one: the same speed. The numbers: `docs/performance.md`.
- **Pages that drop many nodes a frame collect them faster**: the JavaScript engine no longer asks each node object a collection frees for the values it holds when it holds none, and the browser frees a removed tree without a list of its own for each. A page that builds and drops 10 000 nodes a frame: the collection that frees them went from 3.5 to 2.8 ms, its script stage from 12.2 to 11.4 ms a frame. The numbers, and what was measured and not kept: `docs/performance.md`.
- **Developer tools: panels you dock** (the toolkit's docking, gui_toolkit 0.71). The panels (Console, Elements, Network, Application, Performance, Memory) are stacks of tabs: drag a tab out of its strip and squares show over the stack under the pointer (into it, or beside it at a side), at the edges of the panel and between the tabs of a strip, with a translucent preview of where it lands; let go elsewhere, it floats over the panel (moved by its strip, resized by its corner, docked back by a double click on its strip); Escape cancels. Each stack's menu (its button, a right click or the menu key on a tab) does all of it from the keyboard; Ctrl+Tab in a stack shows its next panel. The bars between stacks resize them and fold the second one (a double click, Enter). The Elements panel has the same for the DOM tree and the views of the chosen node (Styles, Computed, Layout, Event Listeners, Accessibility): Styles below the tree, Computed beside it, one of them floating. The layouts are kept in the profile (`browser.devtools.layout`, `browser.devtools.elements.layout`, one line each); they replace the drawer and the side pane's place (`browser.devtools.drawer`, `drawer_tabs`, `drawer_tab`, `browser.devtools.elements.sidebar`, `side_tab`), whose values a profile had become the new layouts (the drawer's tabs a stack under the others at its height, the side pane below the tree or folded as it was). By default the layout is the one before: one stack of the panels, the tree with its views at its right.
- **Built with Odin dev-2026-11** (`odin.version` and the CI's pins; the toolkit v0.70.0): `wren.exe` links the whole C runtime in (libcmt, libucrt, libvcruntime: Lexbor and the Rust libraries are built against it, as Odin's own C library is) and imports no runtime DLL; WOFF tables inflate through the new `core:compress/deflate`, bounded by their declared size.
- **Developer tools: panes you size.** The panel docked under or beside the page goes from a header and a row to all the window but a strip of the page (it was held to 70 %); a floating one shrinks further. The Network tab's request details and the Application tab's value pane are resized by their bars (the network bar's drag ran away from the pointer; the value pane's bar did nothing).
- **Classic scroll bars** (`layout.scrollbar.overlay`, off by default on every system, as Chrome and Edge on Windows and Linux): the page's scroll bars and those of scrollable elements take room instead of covering the content, with an arrow button at each end (a press scrolls a line, `browser.scroll.key_line_px`; held, it repeats after 250 ms every 50 ms):
  - the page's bar comes out of the initial containing block: `document.documentElement.clientWidth` is `innerWidth` less the bar (15 px, `layout.scrollbar.classic.width_px`), `100vw` and media queries still see the whole window, a full-width footer ends where the bar begins; fixed boxes and sticky ones keep to what the bars leave;
  - an element with `overflow: scroll` has its bars whether it overflows or not, `overflow: auto` when it overflows (decided after a pass, laid out again: the first comparison of a layout may add or take bars away, the later ones only add, at most three more passes, so a bar that makes its content fit stays as in Blink); they sit between the border and the padding, a specified `width` keeps its border box (the bar comes out of the content: `clientWidth` less the bar), and an auto width grows by it;
  - `scrollbar-width` (`thin`: 11 px, `layout.scrollbar.classic.thin_width_px`; `none`: no bar, it still scrolls) and `scrollbar-gutter` (`stable`, `stable both-edges`, for `overflow: auto` and `hidden`, on the root element too) are honoured; `scrollbar-color` paints them;
  - colors: `layout.scrollbar.classic.thumb_color`, `track_color`, `arrow_color`, and `browser.scrollbar.dark.classic_*` in the dark scheme;
  - a viewport less than two arrows long either way (a tiny frame) has no bars; a box smaller than its bars keeps its specified size; a box with no width or height shows no auto bars (they would only make it grow, as in Blink); a replaced element has none of the page's (a `<textarea>` counts its own bar in its natural width, none with `overflow: hidden` or `scrollbar-width: none`); a box in a vertical writing mode keeps its bars over its content;
  - the body's `overflow` goes to the viewport only when the body has a box and neither it nor the root element has paint containment (CSS Contain 2);
  - `getComputedStyle()` widths and heights count the bars' room (a specified width round-trips);
  - quirks mode: the body that fills the window counts the top margin a first child collapses through it, as Blink does (such a page no longer scrolls by that margin);
  - `wrentool compare` shows Edge's scroll bars too (no `--hide-scrollbars`).
  `layout.scrollbar.overlay` on: the thin bars drawn over the content, as before. Tests: layout `page_bar_takes_room`, `page_bar_follows_the_content`, `page_bar_scroll_none_overlay`, `box_bars_take_room`, `box_scrollbar_gutter`, `box_bar_without_oscillation`; e2e `page_scrollbars`
- **Scripts that build much of their page every frame run faster**: a new element or text node and its JavaScript object are made in one call to the browser instead of four, `document` is no longer asked of the browser at each read, the JavaScript engine calls the DOM's attribute getters and the window's `document` without leaving its fast loop, and converts the values of DOM calls and finds a platform object's data with fewer calls. A page that builds 10 000 nodes a frame: its script went from 11.1 to 8.6 ms a frame, the collection that frees the nodes it dropped from 4.2 to 3.7 ms. The numbers, and what was measured and not kept: `docs/performance.md`.
- **Pages that rebuild much of their document every frame cost less to draw**: the browser no longer walks every inserted subtree for images after each change (the document keeps a list of its `<img>` and `<input>` elements, as it keeps one of its `<meta>`), and the boxes and lines of a multi-column flow are placed in the column of the box before them when they lie inside it, instead of being cut against every column. A page of 2 500 list items in six columns rebuilt every frame: the image search went from about 0.07 ms a frame to nothing, the finishing of a layout pass from 0.32 to 0.27 ms, the scan of every box after a frame from 0.13 to 0.07 ms. The numbers, and what was measured and not kept: `docs/performance.md`.
- **Pages laid out in columns cost less to paint each frame**: after a frame that changed the document, the browser looks at every box for the largest paint and for layout shifts; a box in a multi-column flow took the long way there (all of its rects, the checks of a paint candidate) and now takes the union of its fragments at once. A page of 2 500 list items in six columns rebuilt every frame: that look at its boxes takes about 0.19 ms a frame instead of 0.40, its frames' CPU work 19.9 ms instead of 20.3. The numbers, and why the layout steps' records were measured and left as they are: `docs/performance.md`.
- **Menus are dense and scroll when the window is too low for them** (gui_toolkit 0.69.0): the rows of the main menu, the context menus, the tab menu and the drop-downs are 29 px for the interface's 15 px text (were 33), as Windows 11's and Chrome's; a menu taller than the window is as tall as it, placed again when the window is resized, and scrolls (wheel, scroll bar, the keyboard's selection brought into view) instead of being cut off at the bottom.

### Fixed
- **The interface's names and protocols match ASCII case alone** (gui_toolkit 0.73.0): the developer tools' server takes `Ho\u017Ft:` (a long s U+017F) for no Host header and `localho\u017Ft` for no localhost, nor `Sec-WebSocket-\u212Aey` (a Kelvin sign U+212A) for the WebSocket key; a font family written with a Kelvin sign or a long s is not the family whose name has a `k` or an `s` (on Linux fontconfig's default font is no longer taken for it). Searches, find in page and type-ahead still fold case by Unicode.
- **`postMessage(undefined)` arrives as `undefined`**: a message's data was taken for a missing one and became `null` (the default of `new MessageEvent()` and `initMessageEvent`, which keep it).
- **The web platform's names and keywords are matched ASCII case-insensitively everywhere**: tag and attribute names (selectors, `getAttribute`), CSS keywords and type selectors, header names and methods, MIME types, cookie attributes, CSP sources, encoding labels, `<script type>`, `rel`, `sandbox`, `allow` and the other attribute keywords no longer take a non-ASCII letter that Unicode folds to an ASCII one (the Kelvin sign U+212A for `k`, the long s U+017F for `s`) for that letter: `LINK` written with a Kelvin sign is no `link`, a `ſecure` cookie attribute is no `Secure`.
- **Windows opened by a sandboxed frame are sandboxed**: a popup that a sandboxed iframe opens is sandboxed as the frame is (no scripts without `allow-scripts`, an opaque origin without `allow-same-origin`), unless the frame allows `allow-popups-to-escape-sandbox`, and the frame may still navigate the window it opened. `window.open("about:blank#x")` opens the blank window at once with that address, and `window.open` resolves a relative address against the document's base URL (a srcdoc frame's is its parent's).
- **`::backdrop` background images**: the backdrop of a modal dialog, a showing popover or the fullscreen element shows its `background-image` (and `mask-image`); the image was never requested, so a backdrop drawn with a picture or a pattern stayed bare.
- **Form keywords are matched ASCII case-insensitively**: an input's or a button's `type`, a form's `method` and `enctype` written with a non-ASCII letter that lowercases to an ASCII one (the Kelvin sign U+212A for `k`) are no longer taken for the keyword (`type="checKbox"` made a checkbox).
- **CSS keywords are matched ASCII case-insensitively**: a keyword written with a non-ASCII letter that lowercases to an ASCII one, as the Kelvin sign (U+212A) does to `k`, is no longer taken for the keyword (`mar\212A` was the system color `mark`).
- **`scrollIntoView` with classic scroll bars**: the document scrolls an element to the end or the center of what its scroll bars leave of the window, not of the whole window (an element brought to the right edge stayed 15 px under the bar).
- **A window opened by `window.open` keeps the Window of its first blank document**: `w = window.open(url); w.onload = ...` and `w.foo = 1` now apply to the page that loads in it when it is of the same origin, as in other browsers; the opener's script found no window to set them on (the blank document was closed when the navigation started). A page of another origin, or one whose Cross-Origin-Opener-Policy puts it in another browsing context group, still gets a window of its own.
- **The site's changelog shows each highlight whole**: a release's highlight written over several lines of its note was cut after the first line (and to its first sentence), on the changelog page and its classic presentation.
- **SharedArrayBuffer between a page and its workers or frames**: what another agent wrote in shared memory is seen as soon as the next event runs. A typed array of a shared buffer read through a cache of the engine that only a WebAssembly call refreshed, so a worker told by a message that the page had written 3 still read the 2 it had written itself.
- **Frames after back and forward**: going back (or forward, or reloading) to a page that was not in the back/forward cache shows each of its frames at the entry it had there (the page it had navigated to) instead of its `src`, and the steps of its frames stay in `history.length` and the back and forward buttons; from the back/forward cache, a position between a frame's steps moves the frame there.
- **`text-align` in text fields**: `center`, `right` and `end` (and `start` in a right-to-left field) place the value and the placeholder in the field while they fit in it.
- **Text fields with a small `line-height`**: a field with an auto height is never shorter than a line of `line-height: normal` (as Chromium), and text taller than the content box shows in the padding instead of being cut at the content box.
- **Middle-click autoscroll in both axes inside a scroller that moves one way**: the session offers the axes of the scroller under the pointer and of those around it and the page, and what the scroller has no room for goes to them, so a panel that scrolls down on a page that scrolls sideways scrolls both ways (and its marker and cursor show four directions).
- **`text-overflow: ellipsis` on text fields**: a placeholder, and a value while the field is not focused, wider than the field end with an ellipsis instead of being cut.
- **An absolutely positioned child of a flex or grid container with no top or left sits where it would as the sole item**: `align-items: center` centres it, `justify-content` and `justify-self` place it along the row (CSS Flexbox §4.1, CSS Grid §9.1), so a search field's icon lines up with its placeholder.
- **Table rows grow to their cells' content when the cells have a height** (`td { height: 36px }`, a compact data table): a cell's height is a minimum, so a description that wraps or a flex row of chips no longer spills over the next rows (CSS 2.1 §17.5.3).
- **Crash recovery keeps the tabs when a start that was restoring them is killed while it saves them.** Windows holds the file it was renaming for a few seconds after such a process ends; the next start could not read it, found nothing worth keeping and deleted it, so the tabs were lost. That start now reads the file, opens a blank page and saves the tabs in a crashed-session file.
- **`document.createCDATASection()`** in XML documents (an XHTML page, `createDocument()`'s, `DOMParser`'s): it makes a CDATA section of that document, serialized as `<![CDATA[...]]>`, and throws `InvalidCharacterError` for data containing `]]>`; an HTML document still refuses it (`NotSupportedError`). It always threw before.
- **Back and forward through frames**: the back button after following a link inside a frame takes the frame back and leaves the page where it is, as other browsers do; `history.length`, `history.back()` and `history.go()` in a page count and move through its frames' navigations too, and `navigation.back()` / `traverseTo()` in a frame move the page with it when they have to (HTML's joint session history).
- **A frame keeps the Window of its initial about:blank**: when a frame's first document is of the same origin as the blank one it replaces, what a script set on the frame's window before it loaded (`iframe.contentWindow.foo = ...`, its listeners, `contentWindow.navigation.onnavigate`) is still there for that document, as HTML says; `history`, `customElements` and `navigation.activation` are the new document's.
- **Two browsers of one process closing at once**: the second joined the shutdown watchdog the first had already freed (a crash at exit, seen when both ended together); the teardowns under way are counted, the last one stops the watchdog.
- **The history tree's text follows its zoom** (about:history#tree): during an animated zoom (+ / -, the zoom buttons, Fit, Current) the nodes' titles grew or shrank in a jump of the 8 % steps text is laid out at, and at rest they stayed up to 8 % smaller than their nodes; the text laid out at a step is now drawn scaled to the zoom's exact size, frame by frame. Page zoom and the interface's zoom were not affected (they do not animate; their text is laid out at its size).
- **Margins collapse through an empty box of `height: 0`** as they do through one of `height: auto` (CSS 2 §8.3.1): a clearfix of zero height between a paragraph and a heading (Google's AI mode answers) added its neighbours' margins instead of keeping the larger.
- **Stylesheets of a page resolve their URLs against its base URL**: the `<base href>` of the document, not its address, for `<style>` sheets and constructed ones (`@font-face` sources, `url()` images, `@import`), `<link rel=stylesheet>` addresses and inline style images. A copy of a Google page saved with `<base href="https://www.google.com/">` asked Google Sans at `file://fonts.gstatic.com`.
- **`overflow: clip` makes no block formatting context** (CSS Overflow 3), unlike `hidden`: the margins of its children collapse with its own again, and floats are not contained. The empty list items Google's AI mode hides with `block-size: 0; overflow: clip` kept a list item's bottom margin inside the list.
- **Form controls take a line height of their own**: `input`, `button`, `select` and `textarea` reset `line-height` to normal, the font's weight and style, `letter-spacing`, `word-spacing`, `text-transform`, `text-indent` and `text-shadow` (the whole font shorthand of `-webkit-small-control`, and the text properties of the HTML rendering section), instead of inheriting them; and a `<button>` sits on the baseline of its content also when its overflow is hidden. The 20 px link chips of Google's AI mode no longer made their lines 3 px taller.
- **The `clip` property**: `clip: rect(top, right, bottom, left)` (commas or spaces, `auto` edges) clips an absolutely positioned box, as CSS Masking 1 says; it was ignored, so the visually hidden skip links of Google's search pages ("Passer directement au contenu principal") showed over the logo at the top left. It clips through the clip-path group, with a clip-path the two rects intersect; `getComputedStyle` serializes it.
- **URLPattern matches as the standard says**: a component's pattern is compiled to its ECMAScript regular expression (the `v` flag), so `:name` segments are lazy, a repeated group captures all its repetitions (`/:path+`), custom groups take named groups and class set operations, and invalid escapes throw; a relative `pathname` resolves against `baseURL`'s path; `exec()` and `test()` of a dictionary honour its `baseURL`; ports are canonicalized with their protocol (`http` and `80` is the default port); a hostname with a forbidden character throws; group names may be any JavaScript identifier; `URLPattern(string, {ignoreCase})` honours the option.
- **Attr nodes have a document**: `attr.ownerDocument` is the document that made it, or its element's (it follows an element moved to another document), where it was always `null`; `cloneNode()` and `importNode()` copy an Attr; `createAttributeNS()` checks its qualified name as `createElementNS()` does (`"p:"` throws `InvalidCharacterError`); appending another window's document throws `HierarchyRequestError`, not a `SecurityError`.
- **International domain names follow the Bidi rule** (UTS #46 CheckBidi, RFC 5893): in a domain with a right-to-left label, a label that mixes directions as the rule forbids (`look־out.net`, `يa`) makes the URL invalid, as in other browsers.
- **Anchor links, back and forward within a page and the Navigation API's scrolling**: a fragment navigation (a link to `#id`, `location.hash`, `navigation.navigate("#x")`) scrolls to its element at once, before the script that asked goes on, and makes it `:target` (which never matched before); back and forward within a document put the scroll positions the entry was left at back at once, before `hashchange`; `pushState` no longer scrolls to the fragment of its URL; an intercepted navigation scrolls when its handlers are done, or at `event.scroll()`: a traversal restores the entry's positions unless the page scrolled meanwhile, a push, a replace or a reload goes to the fragment or the top (`intercept({scroll})`).
- **A document made by `createHTMLDocument` (or `DOMParser`) checks what is inserted into it as the page's does**: a text node, a second element, a fragment with text or two elements, a document, or an element before its doctype throw `HierarchyRequestError` instead of being inserted; `replaceChildren` on a document checks the new children as if the old ones were gone.
- **URL setters as the URL Standard has them**: `host = "example.com:"` (or `:abc`) sets the host and keeps the port, a port out of range keeps the host it set; `username`, `password` and `port` do nothing on a URL with an empty host (`sc:///`); `host = ""` does not empty the host of a non-special URL with credentials or a port; a file URL's host that is `localhost` once percent-decoded is the empty host.
- **The `inert` attribute keeps the focus out**: an element in an inert subtree (or outside the open modal dialog) can no longer be focused by `focus()`, a click or Tab.
- **Opening a dialog focuses what the HTML standard says**: a descendant with `autofocus` that can have the focus (one hidden, disabled or in a closed nested dialog is passed over), else the first one Tab reaches (a shadow host that delegates focus for what it delegates to, nothing inside another shadow tree), else the dialog itself; nothing for a dialog out of the document or inert. On close the focus goes back where it was before when it is still in the dialog, and from a modal dialog always; a focus left in a closed dialog goes to the body.
- **A `<select>` picks its option again only when something asks for it** (an option inserted or removed, a `selected`, `multiple` or `size` attribute, `option.selected`, a form reset): `selectedIndex = -1` on a drop-down stays until then, where every read selected its first option again.
- **`scrollIntoView` scrolls the containers the element is in**, innermost first, then the page: an item of a scrolling list or chat panel below its fold is brought into view (only the page moved before).
- **No crash when a frame is removed during an event of its document**: a parent's listener on a node of a frame (an image's `load` or `error`...) that removes the frame no longer frees the frame's document under the event being dispatched; it is closed once the dispatch is over.
- **Dialogs close as their `closedby` says**: a click outside an open dialog whose `closedby` is `any` closes it (light dismiss: a `cancel` it may cancel, then `close`; a click on the backdrop of a modal one counts as outside), and Escape asks the dialog on top to close whether `show()`, `showModal()` or its `open` attribute opened it (it was the top modal dialog only), unless its `closedby` is `none`.
- **URLs parsed as the URL Standard says where Lexbor did not**: a host whose last label is digits past 2^32 then letters (`1.12345678901c`) is a domain, not a refused IPv4 address; a dot segment followed by a query or a fragment (`/a/b/%2e%2e?query`) keeps its `?` or `#`; `^` in a path is percent-encoded; the last space of an opaque path before a query or a fragment becomes `%20`; the pathname of a path that begins with an empty segment (`non-spec:/.//p`) no longer starts with `/.`.
- **Attributes keep their namespace**: an attribute set with `setAttributeNS` (or `setAttributeNode` of a namespaced `Attr`) is one of its own beside the plain one of the same name, and does nothing the plain one does (a namespaced `style`, `src`, `on*`, `id`, `slot` or `open` no longer sets the inline style, loads a frame, registers a handler or opens a `<details>`); `Attr` objects keep their namespace, prefix and identity (`getAttributeNode` / `attributes[i]` give the same object, one removed by `removeAttribute` loses its `ownerElement` and keeps its value), `setAttributeNode` replaces the attribute of the same namespace and local name, `getAttribute` on an HTML element no longer finds an upper-case name set with `setAttributeNS`, MutationObserver records carry `attributeNamespace`, `lookupNamespaceURI` and `lookupPrefix` read the `xmlns` attributes by their namespace.
- **Setup's status line no longer blinks**: the dialog reads the disk again whenever the system says the integration changed, and each read put "Working�" over the status and greyed the buttons; only installing and uninstalling show it now.
- **The downloads drop-down**: a right click on a row opens the row's menu (Open, Show in folder, Copy download link, Download again, Delete the file, Remove from the list) over the drop-down, which stays open behind it; it used to close the drop-down. A press beside the menu closes only the menu (`ui.menu_nested`).

## [0.6.27] - 2026-11-03

### Changed
- **Pages that restyle everything style faster**: before the style threads share a full pass, the browser weighs the document's subtrees in one walk instead of three, and a pass takes the slots of the pass recycled before it instead of faulting fresh memory in. A page of 10 000 elements restyled whole every frame: its styles 0.74 ms a frame instead of 0.90, its frames' CPU work 3.25 ms instead of 3.77. The numbers: `docs/performance.md`.

### Changed

### Fixed
- **Plantage en changeant de page après une page riche en variables CSS** : les couches de propriétés personnalisées gardaient des noms (et des noms retirés) qui pointaient dans les règles de la feuille ; quand l'index des règles était reconstruit entre deux passes de style, la comparaison des anciens styles avec les nouveaux (transitions) lisait de la mémoire libérée (`string_eq`, violation d'accès). Reproduit en allant de tailwindcss.com à getbootstrap.com dans la même fenêtre. Les couches possèdent maintenant leurs chaînes (test `custom_layer_owns_its_strings`). Au passage, la comparaison des portes `@media` ne lit plus les listes d'une feuille retirée.
- **`<svg>` en ligne : le CSS de la page s'applique aux éléments intérieurs** : les règles de la page visant un élément dans un `<svg>` (`.logo__text { fill: ... }`, `svg path { stroke: ... }`, `light-dark()`, `opacity`, `display: none`) étaient ignorées ; seul l'élément `<svg>` lui-même recevait son style. Les valeurs calculées sont maintenant écrites dans l'attribut `style` de chaque élément qu'une déclaration vise (elles passent avant les attributs de présentation, après le `style` de l'élément). Le logo de MDN reprend ses couleurs.
- **`<button>` en `display: block` ou `flex` : largeur du contenu** : un bouton dont la largeur est `auto` se dimensionne sur son contenu même quand la page le met en `display: flex` ou `block` (HTML §15.5). Il remplissait toute la ligne ; sur la page d'accueil de MDN, le bouton « Search » est maintenant de la bonne largeur et centré.
- **`<dialog>` : style par défaut de la spécification** : un `<dialog>` est hors flux, centré, de taille `fit-content` (`position: absolute`, `margin: auto`). Sans cela, un dialogue fermé que la feuille de la page met en `display: flex` (Bootstrap 6) poussait toute la page de 185 px vers le bas ; getbootstrap.com passe de 50 % à 9 % d'écart avec Edge.
- **Feuilles de style liées : ordre du document retrouvé après le chargement** : pendant que le parseur révèle la page, les `<link rel="stylesheet">` détachés gardent leur feuille mais sont classés comme s'ils n'étaient nulle part, donc dans l'ordre d'arrivée du réseau. Une fois les éléments de retour dans l'arbre, rien ne reclassait les feuilles : sur python.org, `mq.css` (blocs `@media`) passait avant `style.css` et perdait la cascade (bouton Donate affiché en bloc, logo masqué). Les feuilles sont maintenant reclassées dès que leur propriétaire revient (test `sheet_order_after_detached_owners`).

- **The classic look's new-tab button (and every classic tab) no longer ends its feet in a cut** (`chrome_style.odin`): the outline started and ended at the edge of the tab's box, leaving a flat strip along the bar that stopped sharply; it now starts and ends where each foot's curve meets the bar's line.
- **A normal (not elevated) Wren no longer takes `WM_DROPFILES` / `WM_COPYDATA` from processes of a lower integrity** (`local_paths.odin`, security review of 2026-10-25, finding 11): the window let those three messages through the Windows message filter whether or not the browser ran as administrator, though the reason (an elevated browser must still take drops from Explorer) only holds for an elevated one; a sandboxed process could then send a forged drop and have any path opened. The filter is now set only when the process is elevated (`instance.is_elevated`, as for the single-instance window). Not verified with a real low-integrity sender.
- **The update check's answer and file are checked** (`update_version_ok`, `update_page_ok`, security review of 2026-10-25, finding 10): the release's `tag_name` was kept as it came and written a line at a time to `update.txt`; a tag with a line break (`99\nurl=file://...`) wrote a `url=` line of its own that the next start read back, and the "vX is available" button of Setup opened it as an address. A version must now be letters, digits, `.`, `+` and `-` (64 at most), a release page an `https://` address on one line with no space or control character, both when the answer arrives and when `update.txt` is read; anything else is dropped. Test: `update_check_test.odin`.
- **The control pipe's client no longer lets a server that is not Wren act as the person** (`conn_windows.odin`, security review of 2026-10-25, finding 7): `wren ctl` opened the pipe with the default impersonation level, so a process that had taken the (predictable) pipe name first, with the privilege to impersonate (a service account), could act with the person's identity once the client wrote to it. The pipe is opened with `SECURITY_SQOS_PRESENT | SECURITY_IDENTIFICATION`: the server can see who connected, not act as them. Not changed, left as a proposal: checking the server's process id against the one expected (`GetNamedPipeServerProcessId`), and the pipe names, which stay predictable.
- **A damaged IndexedDB checkpoint file cannot make the journal be cut at a negative offset** (`idb.ck_read_directory`, security review of 2026-10-25, finding 8): the sizes read from the `.widx` file are 64-bit numbers that were turned into signed ones before they were compared (a journal length with the top bit set passed `> journal_size`; a section's offset and length could add up past the file). Every number is now compared as unsigned against the file (a section must lie in it, hold at least as many bytes as it has records, and the counts of entries cannot exceed the directory). Needs a write access to the profile to matter. Test: `checkpoint_hostile_test.odin` (fails on the code before).
- **The report of a session that ended without one is no longer empty on a loaded machine** (`crashtrace.begin_session`, security review of 2026-10-25, finding 9): the thread that reads the previous session's file was started before the text it reads was set, so it could read `""` (no process id, no event found). The text is set first.
- **`wren ctl stop` no longer ends a program that took the number of a Wren that had ended** (`spawn_windows.odin`, security review of 2026-10-25, finding 6): the session file of `wren ctl start` holds a pid; when the Wren was closed by hand or crashed and Windows gave its number to another program, `stop` waited 15 s for that program and then ended it (measured: an unrelated `ping.exe`). `start` now writes who the process is (its creation time and its program, from its handle); `stop` opens the process once, checks both against the file before it waits for it or ends it, and leaves anything else alone (a word on stderr, exit 0, the session file removed). A session file of an older `wren ctl`, which does not say who, names nobody: nothing is ended. Test: `tools\ctl_stop_e2e.ps1` (fails 6 of 9 checks on the build before), `spawn_windows_test.odin`.
- **`wren ctl eval` no longer puts a secret where a page can read it, and a page cannot answer for another tab or add a line to the protocol** (`remote_shell.odin`, `remote_json.odin`, security review of 2026-10-25, finding 5): the answer of a script came back as a console line starting with a prefix made at each start, "so that a page cannot forge it". The line goes through the `console.log` of the page, which a page can replace: it read the prefix at the first `eval` (or the first `wait load`), then answered in place of the script, for a question waiting in another tab too, and a value with a line break in it cut the JSON line of the protocol in two (the client hung). The mark is now a constant, and an answer counts only if it comes from the tab the question was asked in, for an id that waits, the first time; the value is checked to be one JSON value on one line before it is put in a reply (anything else is an error). A page can still lie about the value of what it is asked, as it can about `document.title` to its own scripts; `docs/remote.md` says so. Tests: `remote_page_e2e.ps1` (fails 4 of 5 checks on the build before), `remote_forge_test.odin`.
- **The programs the browser starts are the system's, by their full path** (`desktop.system_file`, `crashtrace`, security review of 2026-10-25, finding 4): the report of a session that ended without one ran `wevtutil.exe` by its bare name, and `CreateProcess` looks in the working directory before the system folder, so a `wevtutil.exe` planted in the folder a page was opened from ran, without a window, at the next start after a crash or a kill. It is now `System32\wevtutil.exe`, as the application of the process. The same for the two other bare names found in `src`: `explorer.exe` of "Show in folder" (`ShellExecute` searches the working directory too; now `C:\Windows\explorer.exe`) and the `cmd.exe` of the deferred clean-up script of the installer (now `System32\cmd.exe`); `icu.dll` (the time zone's name) is loaded from the system folder only. Test: `tools\planted_program_e2e.ps1` (fails on the build before), `crashtrace_test.odin`, `system_windows_test.odin`.
- **The policy file is read beside the executable, no longer from the working directory** (`policy_file.odin`, security review of 2026-10-25, finding 3): without `--policy FILE` the browser read `policies.txt` from the working directory, at the highest layer (it locks any preference). Windows may give a program the folder of the document it opens as its working directory, so an archive holding `page.html` and a `policies.txt` with `security.file_access.policy` set to `all`, or `security.csp.enabled` to `false`, could widen what a local page may read. The file is now `policies.txt` in the executable's folder (the Start menu shortcut already had that folder as working directory, which is what `docs/desktop-integration.md` meant); `--policy FILE` is unchanged. Test: `tools\policy_file_e2e.ps1` (fails on the build before) and `policy_file_test.odin`.
- **A download name with a very long extension no longer ends the browser** (`download_file_name`, security review of 2026-10-25, finding 2): a server answering `Content-Disposition: attachment; filename="a.xxxx…"` with 250 `x` made the name shortener index past the end of the name's stem (a bounds-check panic: every tab closed), with no action from the person. The cut is now one procedure that keeps whole characters, drops an extension as long as the limit, never leaves a dot or a space at the end, and the device-name test (CON, NUL, COM0-9, LPT0-9 and the superscript digits) looks at the part before the first dot, as Windows does (`con.tar.gz` was written as the console device) and runs after the cut, so a cut cannot make a device name. Tests: the very long extension at nine limits, ninety hostile names (empty, dots, controls, bidi, reserved characters, devices, invalid UTF-8, 1000 bytes in one- to four-byte characters), and 30000 random names against the same invariants.
- **An address chosen by a web page is never taken for one the person typed** (`src/browser/nav_trust.odin`, security review of 2026-10-25, finding 1): `navigate` took "no `from`" for "the address bar", and the reload, the history, the new-tab paths (a `_blank` link or form of a frame, the menu's "Open link in new tab", Duplicate, Reopen closed tab) passed none. A page that asked for `about:sites?clear=*&type=all` was refused but left that address in the tab and in the history; the next F5, Back or Forward ran it as the person's own and cleared the cookies and the storage of every site (a framed `<form target=_blank action="about:sites">` with two hidden fields did so with no click at all, and `file://127.0.0.1/c$/...` or `file:///C:/...` asked the same way was opened, over SMB for a share, with the browser's rights). `navigate` now takes an explicit `Nav_Origin` (`.User`, `.Replay`, and `.Page`, the default: a navigation nobody vouches for has no privilege). The effects of `about:sites?clear=`, `about:cache?clear=1` and `about:wren?action=` / `choose=` / a licence file run only for the person or from the page itself, never for a page or a replay; a page's address loses them (it is `about:sites` in the tab and the history); `file:` and shares from a web page, or from a local page that the loader would refuse, are refused before anything changes (a line in the console of the page that asked, no history entry, no new tab left empty); a deferred navigation keeps its origin; `location.replace` is judged before it replaces the entry. Test: `tools\nav_trust_e2e.ps1` (fails 9 checks on the build before this fix) and the origin by address table in `nav_trust_test.odin`.
- **The content blocker no longer lets the first page of a session through unfiltered** (`fetch.hold_requests`, `engine_build.odin`): until the compiled index of the lists is loaded (no valid cache in the profile: first start, a throwaway profile, a new index format) only the small base list was in force, so a YouTube watch page opened at once kept `ytInitialPlayerResponse.adPlacements`, `adSlots` and the ad entries (the next page, with the index there, was clean). The requests to the network now wait for the compile job (at most 20 s), then go through the lists.
- **Ad data of `/youtubei/v1/player` is removed from its answers**: a `set-constant ytInitialPlayerResponse.<key> undefined` rule also prunes `<key>` from the answers of `/youtubei/v1/player` (the page asks for the next video that way), before the list's `$replace=` / `trusted-replace-*` filters, so `playerAds` and the ad entries no longer stay behind a renamed `adPlacements` (`"no_ads"`).
- **`trusted-replace-xhr-response` / `trusted-replace-fetch-response` with a bare URL pattern** (`/\/player(?:\?.+)?$/`, `player?`) applied to every answer of the site instead of the matching URLs; `trusted-rpfr` and `trusted-rpxhr` are known aliases now.
- **A property a `set-constant ... undefined` hook defines is no longer listed by `Object.keys` / `JSON.stringify`** (`ytInitialPlayerResponse.playerAds` showed up as an accessor key).
- **`wren ctl start` with a throwaway profile does not download the content blocker's lists** (`--pref blocker.update.enabled=true` turns that on): a few seconds of CPU after the start were taken for the CPU of an idle Wren by the end-to-end tests on a machine with a network.
- **The content blocker no longer leaves a request's context allocated when the browser closes during the download of its lists** (`updater_stop` cancelled the request, which sends no more events, and what they carried stayed: found by the check build of the CI, whose machine downloads the lists; reproduced here with `blocker.update.start_delay_s=0`).
- **A crash report on a thread other than the main one** no longer needs the stack to make a thread: the thread that writes it is made at start-up and the handler only wakes it (a stack overflow on a thread leaves one page; making a thread took more on some versions of Windows and the handler died of its own access violation, without a report).
- **The browser's exit forgets the requests the performance timeline still described** (`page.timeline_shutdown` was only called by the end-to-end tools): a block of 9.5 KB was left allocated, found by the check build of the CI.
- **A page with video plays on a machine that has no audio device** (a server, a CI runner, a remote session without sound): the player used to stop with a media error (`the audio device is gone`). It now gets an output that lets the audio go by in silence at the pace of the clock (`src/media/audio_null_windows.odin`), so the media clock follows it as usual and the video plays, as in the browsers.
- **The developer tools resize properly, docked and in their own window.** (1) Docked, the panel ignored its size: `devtools_panel` sets the next box's style itself (`ui.next` replaces, it does not merge), so the width or height the call sites gave was dropped and the panel shared the room half and half with the page; dragging the splitter changed the saved size and nothing on screen. The size is now the panel's place. (2) The panel's own window had an opaque HWND swap chain, which the system maps onto the new size while the window is resized (the last frame stretched and squashed): it is made as the main window is, a composition swap chain with the fixed surface of `browser.window.fixed_surface` (`fixed_surface_size`, shared; toolkit 0.23.0 `render.surface_create(transparent, fixed_size)`), a resize step is shown at once (`browser.frame.resize_immediate`) with two frames in flight (`pacer_latency`, shared with the main window). (3) While Windows runs the size loop of one window, the other was not drawn at all (the panel's window stayed frozen for the whole drag of the browser window, measured 6 s without a frame): each window's loop now draws the other. `tools\devtools_resize_e2e.ps1` checks the three (a strip of each window read from the screen after every resize step must not be scaled); `tools\dt_resize_bench.ps1` measures the frames.
- **`wren ctl shot --scale n` no longer reads freed memory.** The picture made by the scaling was released where its block ended, before the PNG was written from it: a capture with a scale other than 1 gave a blank or garbage image, or ended the connection.
- **Thin 3D planes no longer make their whole context split.** The order and the crossing of the planes of a `preserve-3d` context were worked out on each layer with the margin it is rasterized with (one device pixel on each side, and the rounding to texels): a plane seen almost edge-on, such as the rim of a coin or of a card, seemed to reach into every plane it touches, so all of them were taken to cut through each other and were split into hundreds of pieces (the licence seal disappeared). The geometry is now that of the layer without its margin.
- **Custom elements**: `document.importNode()` (Polymer's way of stamping a template) and `cloneNode()` of a node of the document now upgrade the clone's elements of a defined name before they return (the contents of a template stay inert); and a custom element reaction's own DOM calls (a `connectedCallback` appending a stamped template) run the reactions they queued before they return, as the specification's stack of element queues does, where they used to wait for the outer reaction to end. YouTube's elements (`ytd-watch-flexy`'s `attached` called `preparePlayer()` on a player not upgraded yet) stopped on `TypeError: not a function`, which left the home page and the watch page without their contents.
- **Template contents have a document of their own** (HTML "template contents owner document"): `template.content.ownerDocument` (and that of every node in it) is an inert document, not the page's, so `ownerDocument.createElement("dom-repeat")` (Polymer prepares `<template is="dom-repeat">` this way) makes a plain element that is neither constructed nor given its attributes' callbacks; the documents of `createHTMLDocument` and `DOMParser` are inert the same way (`Document_createElementInert`). A script's insertion of nodes into a tree that is not connected no longer upgrades them (only a connected node is, as the specification says; the parser's `innerHTML` still upgrades what it makes). Before, moving a template's contents into another fragment constructed YouTube's elements inside them, which changed the child indexes Polymer had recorded, left `nodeList[i]` undefined and stopped with `cannot set property '__dataHost' of undefined`, and logged `Polymer::Attributes: couldn't decode Array as JSON: [[shownItems]]`; YouTube's watch page now builds its recommendations, comments and controls.
- **Fullscreen on a page that lays itself out again** (YouTube's player): the window's `resize` event is fired (once per rendering update whose viewport size differs from the last one; it was never fired), the `fullscreenchange` events and the promise wait for the window to have its new size and the page to have been laid out for it (`Fullscreen_Embedder.deferred`, `fullscreen_settled`; they run in the rendering update, before that frame's `resize`).
- **Developer tools, console**: a message of several lines (an error and its call stack) selected alone is shown one line per row in a pane under the list (the folders of the script addresses left out of the stack lines; copying still gives the whole text), instead of one line with `┬Â` marks only. An image answered with an empty body (a `204`, the connectivity pings `new Image().src = ".../generate_204"` that YouTube makes) fires `error` and no longer logs a warning.
- **Incremental layout** could crash (`has_block_child`, a dead box rebuilt) when an attribute that rebuilds an element's box changed inside a box the same pass made again alone (found on YouTube's home page): the boxes a plan took with it are no longer rebuilt as roots.
- A detached `new Image()` never loaded when `src` was set before it was attached to the document; it now starts loading at once (needed by `drawImage`).
- Closing the window after a heavy page (GitHub) could take 5 to 15 s or more: the Wasm module cache wrote every compiled module still queued to its disk cache, each one scanning the folder. It stops after 1.5 s and drops the rest.
- reCAPTCHA's "I'm not a robot" box (google.com/sorry) drew its checkbox in the corner of its card: an inline-block with `height: 100%` now resolves against its container's definite height, and a table beside a float no longer shrinks to its minimum width.
- **Memory on pages with many variables and sheets** (DuckDuckGo's results page, measured): custom properties are layers over the parent's (`style.custom_properties.max_layers`; an element that sets a few no longer copies the hundreds it inherits), the CSS parser keeps its tokens, code points and values in scratch memory dropped after the parse (126 to 45 bytes kept per byte of CSS), validating declarations no longer leaves two computed styles per compiled rule (6.4 to 1.1 KiB), and the mutation journal no longer copies its names to a new arena at every `setAttribute` (it was 80 % of that page's time).
- Image decoding threads end after `images.decode.thread_idle_ms` of idleness and start again on demand: the stack a large decode commits (about 14 MB per thread for an AVIF) goes back to the system. A job still belongs to one owner at a time (its holders keep an identifier, not a pointer).
- **Images appear sooner** (toolkit 0.26.0): a new image texture is no longer zeroed one row at a time (551 driver calls and 1 to 4 ms for a photo), opaque images (every JPEG, most PNG, WebP and AVIF) are uploaded from the decoder's buffer with no conversion pass, and translucent ones are premultiplied a word at a time.

## [0.2.0] - 2026-10-20

JavaScript, inside WebAssembly: WebAssembly is still the only execution engine.

### Added
- **JavaScript.** QuickJS-ng 0.17.0 compiled to a WebAssembly module, pre-initialized at build time and embedded in
  `wren.exe`; one sandboxed instance per page and per JavaScript worker, with a heap cap
  (`javascript.max_heap_bytes`), a clean stop for long scripts (`javascript.slow_script_ms`) and the Wasm deadline
  behind it. On or off globally (`javascript.enabled`) or per site (`javascript.sites.disabled`,
  `javascript.sites.enabled`). A bytecode cache in memory and in the profile. `JS` / `JS stopped` in the status bar.
- **Bindings generated from the specifications' Web IDL** (webref): 2,630 of 4,991 members implemented, the others
  absent ([docs/js/coverage.md](docs/js/coverage.md)). DOM, CSSOM, geometry, UI events, `MutationObserver`,
  `IntersectionObserver`, `PerformanceObserver`, ranges and traversal, custom elements, `CSS.supports` /
  `CSS.escape`; script loading as HTML specifies it (parser order, `defer` / `async`, `document.write`, ES modules
  and import maps, inline handlers, `javascript:` URLs, `<noscript>`, CSP for scripts); `fetch`, `XMLHttpRequest`,
  streams, `Blob` / `FormData`, URL, encoding, `AbortController`, Web Storage, history and location, navigator,
  performance, `crypto` and `crypto.subtle`, `matchMedia`, WebSocket, EventSource, `MessageChannel`, JavaScript
  workers, `structuredClone`, a minimal `Intl`.
- **Shadow DOM**: `attachShadow`, declarative shadow roots (rendered without JavaScript), named and manual slots,
  `:host`, `:host-context()`, `::slotted()`, `::part()` and `exportparts`, `:state()` and `ElementInternals`,
  constructable stylesheets and `adoptedStyleSheets`, event retargeting and `composedPath()`, `delegatesFocus`,
  `getHTML` / `setHTMLUnsafe`.
- **Conformance suites**: test262 (99.92 % of 82,220 runs) and web-platform-tests (4,494 test files, 106,188
  passing subtests), pinned, with committed expectations checked by `tools/test_all.ps1`.
- HTML presentational attributes and quirks mode; `text-align: -webkit-center`; `line-height: normal` from the font.
- Tabs with favicons, loading indicators, drag to reorder and middle-click to close; error pages by cause; downloads;
  optional session restore; more shortcuts (Ctrl+P notice, Ctrl+Shift+PgUp / PgDn, mouse back and forward buttons).
- Local files: Windows paths in the address bar and on the command line, drag and drop of files and folders, folders
  opening their `index.html` or a sortable list of their files, `about:about`; `examples/site/index.html` and
  `about:demos` list every demo by theme.
- Demos: `js.html`, `js-dom.html`, `shadow-dom.html`, `legacy-html.html`, script loading and web API pages.

### Changed

- Text placed vertically as in Chromium: font metrics rounded one by one, half-leading, `vertical-align`, flex lines
  bounded by `min-height`, centered button content, table cells and form control baselines, monospace and keyword
  font sizes.
- Image sizes come from the decoded image; `width` / `height` attributes give the aspect ratio before decoding.
- Shaders precompiled: the start page is drawn about 0.3 s after launch (1.8 s before). Resizing keeps the swap chain
  (a margin and a presented region instead of `ResizeBuffers`); media queries restyle only when their answer changes.
- The event loop runs due timers for at most `browser.loop.timer_slice_ms` per turn once one has run.
- User-Agent `Wren/0.2`.

### Fixed
- About 90 problems found by a review of the whole engine: use-after-frees (microtasks during host tasks, fetch,
  workers, streams), `file:` pages leaving their folder (escaped separators, junctions, links, alternate streams,
  device names), NTLM leaks through `file://server/share`, hostile content that crashed or froze the browser (huge
  `calc()`, exponential `var()`, cyclic `@import`, extreme transforms…), CORS on redirects, lost `localStorage` at
  exit, ten divergences of the incremental restyle and layout, `--pref` erasing profile values.
- Synthetic italics of static web fonts.
- Closing a WebSocket right after a message no longer ends in an error.
- Flaky tests fixed at their cause; CI no longer retries a failed step.

## [0.1.0] - 2026-10-19

The first public build: a browser for Windows where WebAssembly is the only execution engine, with no JavaScript.
Pages name their Wasm modules with `<script type="application/wasm">`; the web APIs are Wasm imports generated from
`api/*.widl`.

### Added
- **WebAssembly runtime**: Wasmtime 49 (Cranelift), compiled-code caches in memory and on disk, a deadline on every
  call, several modules per document, memory64, dedicated workers.
- **Web API from one description**: 21 modules, 289 functions, with generated host trampolines, Odin SDK,
  documentation and conformance tests.
- **HTML and CSS**: Lexbor parsing, cascade layers, custom properties, `:has` / `:is` / `:where`, media and container
  queries, Color 4 / 5, web fonts, transitions and animations.
- **Layout**: block, inline (bidi), floats, positioning, flexbox, grid with subgrid, tables; incremental and parallel.
- **Painting**: a retained GPU compositor on Direct3D 11, transforms, filters, blend modes, masks, exact shadows,
  gradients in every color space.
- **Text** on DirectWrite; **images** through WIC plus built-in WebP, AVIF and SVG.
- **Network and security**: WinHTTP, a Fetch Standard policy layer, cookies, HSTS, Content Security Policy 3.
- **The browser**: tabs, history, find in page, selection, zoom, view-source, `about:config`, frame pacing and
  statistics.
